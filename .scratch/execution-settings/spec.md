# 执行设置：agent 执行参数用户可调

**Status:** ready-for-agent

## Problem Statement

用户面对一批写死的执行约束，无法按自己的模型与工作负载调整：大功能开发单回合工具调用动辄上百次，主任务 200 轮上限虽是失控兜底，但对使用更大上下文窗口的用户有上调需求，撞限即中断当前回合；子代理被同样上限截断时报告不完整，主任务要多轮返工；终端跑构建/测试时 30s 默认命令超时与 120s 硬上限经常不够；compact 后保留多少对话现场、上下文用量告警多早出现，都是纯用户偏好却无法调整。

## Solution

设置页新建「执行」分区，提供四项：主任务工具轮次上限、子代理工具轮次上限、压缩保留对话轮数、上下文告警阈值；现有终端分区补两项：命令超时、最大命令超时。六项默认值与现状完全一致（200 / 200 / 3 / 80% / 30s / 120s），改动即时保存；已开始的执行用开始时的值，下一次执行起用新值（ADR 0017）。防护性上限不暴露为设置。

## User Stories

1. 作为用户，我希望在设置页调整主任务工具轮次上限，以便大任务不被默认上限截断。
2. 作为用户，我希望在设置页调整子代理工具轮次上限，以便复杂委派的报告完整回流。
3. 作为用户，我希望主任务与子代理上限相互独立，以便按两者不同的语义分别配置。
4. 作为用户，我希望打开设置页时看到默认值 200 / 200 / 3 / 80% / 30s / 120s，以便不配置时行为与现在完全一致。
5. 作为用户，我希望输入超出合法范围的值时被阻止或回退，以便不会设置出离谱参数。
6. 作为用户，我希望改动立即保存，以便无需重启应用或任务。
7. 作为用户，我希望正在执行的回合不受中途调小上限影响，以便行为可预期。
8. 作为用户，我希望撞限提示显示当前上限值，以便知道限制来自我的配置而非固定规则。
9. 作为用户，我希望设置在重启后保留，以便配置一次长期有效。
10. 作为用户，我希望设置文件损坏时回退默认值，以便应用不因配置损坏而异常。
11. 作为用户，我希望调整压缩保留对话轮数，以便控制 compact 后保留多少现场。
12. 作为用户，我希望下次压缩立即采用新保留轮数，以便调整无需等待。
13. 作为用户，我希望调整上下文告警阈值（百分比 50–95%），以便对小窗口模型更早收到提醒、对大窗口模型减少打扰。
14. 作为用户，我希望在终端分区调整命令超时（5–600s），以便跑构建/测试不被 30s 打断。
15. 作为用户，我希望调整最大命令超时（10–1800s），以便为长时间命令留出余地。
16. 作为用户，我希望命令超时不允许超过最大命令超时，以便两个值不会矛盾。
17. 作为用户，我希望这些设置集中在与语义匹配的分区（执行类进「执行」、超时进「终端」），以便按直觉找到它们。

## Implementation Decisions

- 分区归属与存储（ADR 0017）：四项执行参数进新建「执行」分区，独立设置文件持久化；终端两项扩展现有终端设置文件。沿用现有设置体系形态：每设置一份 JSON、渲染层设置页分区、get/set IPC、主进程内存缓存。
- 注入模式（ADR 0017）：沿用子代理并发上限的 resolver 范式——agent-core 的任务创建选项与子代理配置扩展逐次解析的取值函数，agent-core 不直接依赖任何存储实现（ADR 0002 边界不破）；终端两项经内置工具工厂的 options 入口注入，与既有 shell 注入同构。
- 生效语义（ADR 0017）：「即时保存、回合开始快照」——主任务与子代理的工具轮次上限在回合开始时读取一次；compact 保留轮数与上下文告警阈值无「进行中」状态，逐次读取。
- 默认值与校验：默认 200 / 200 / 3 / 80% / 30s / 120s；范围 10–1000（两项轮次）、1–10（保留轮数）、50–95%（阈值）、5–600s（命令超时）、10–1800s（最大命令超时）且命令超时 ≤ 最大命令超时；非法输入回退默认值。
- 撞限文案：主任务落库 error 提示与子代理报告截断标记携带动态上限值，替代固定数字（ADR 0016 引入的两处文案）。
- 术语：设置文案遵循 GLOSSARY——「工具轮次（Tool Round）」区别于呈现层「轮次（Turn）」；分区名「执行设置（Execution Settings）」。
- 防护性上限（AGENTS.md 注入体积、@引用大小、文件树扫描深度、read-file/grep 截断等）不进设置（ADR 0017）。

## Testing Decisions

- 好测试只断言外部行为（撞限时机、提示/截断文案内容、compact 保留轮数、告警触发点、设置持久化往返、页面校验），不断言内部调用次序或实现细节。
- 三层既有 seams，不新建 seam 类型：
  1. agent-core 行为层（主 seam）：构造任务/子代理时注入自定义值，断言注入生效与默认值不变；先例为现有主任务满轮撞限测试、子代理截断标记测试。
  2. desktop IPC/store 层：设置文件读写、校验、损坏 fallback、IPC handler；先例为现有各设置 store 与 IPC 测试。
  3. ui 组件层：分区渲染、输入校验、保存调用；先例为现有设置页相关组件测试。
- 默认值回归保障：现有「满 200 轮撞限」测试的数字与语义不变，仍应全绿。
- 不新增 e2e 场景：行为核心在 agent-core 层全覆盖，设置项无跨层集成风险点。

## Out of Scope

- 其余候选参数（MCP 调用/连接超时、浏览器工具超时、web_search 超时与结果数、read-file/grep/glob 截断等）：落为 needs-triage issue 留档，不本次实现。
- 上下文窗口缺省值：Provider Profile 已可逐模型配置，不重复暴露。
- per-task 设置覆盖机制：六项全部为全局设置。
- 撞限文案的措辞改版（仅数字动态化，文本结构不变）。
