# Spec: 启动现场恢复（Launch State Restore）

Status: done

术语依 `GLOSSARY.md`：**启动现场**、**工作台目标**、**会话**、**独立会话**、**项目**、**主题**。本 feature 不涉及 ADR。

## Problem Statement

关闭 CodexLike 再打开，一切从零开始：窗口回到硬编码的 1280×800 居中，且冷启动自动打开的是「排序最前的未归档会话」（置顶 > 最近使用）——不是退出前正在看的那个。用户每次重启都要重新拖窗口、重新找回刚才工作的会话；如果退出前正在看的是一个归档会话或某个项目下的新建草稿，则完全回不去（草稿文本虽在，入口已丢）。

## Solution

引入**启动现场**：随状态变化持续保存的界面现场——窗口位置与大小、是否最大化、退出前的工作台目标与所在视图，整体落在主进程的一个 JSON 文件里。重新打开时建窗前读取并应用；现场指向的会话已不存在时，回退到现有「最近的未归档会话」逻辑。因为保存不依赖正常退出，崩溃或被杀后重开同样恢复。

## User Stories

1. 作为用户，我想重新打开应用后窗口出现在关闭前的位置，以便我的桌面布局不被重启打乱。
2. 作为用户，我想重新打开应用后窗口保持关闭前的大小，以便不必每次重新调整到顺手的尺寸。
3. 作为用户，我想最大化状态下关闭、重开后窗口仍是最大化，以便大屏工作方式原样延续。
4. 作为用户，我想重开后直接回到退出前正在查看的会话，以便接着刚才的上下文继续工作。
5. 作为用户，我想退出前正在查看的归档会话也照常恢复，以便翻查旧会话的工作不被重启中断。
6. 作为用户，我想退出前停在「新建草稿」状态（含其项目关联）时重开回到同样的草稿状态，以便还没发出的第一条想法不因重启丢入口。
7. 作为用户，我想退出前停在设置页时重开仍在设置页，以便没改完的设置接着改。
8. 作为用户，我想在记住的会话已被删除时，重开自动打开最近的未归档会话，以便现场失效也有合理去处。
9. 作为用户，我想在没有任何可打开的会话时，重开停在新建草稿入口，以便与现有冷启动行为一致。
10. 作为用户，我想首次安装启动（无现场文件）时得到默认的 1280×800 居中窗口与现有冷启动行为，以便新用户路径不变。
11. 作为用户，我想应用崩溃或被强制结束后重开，现场照样恢复，以便「恢复」不依赖优雅退出。
12. 作为用户，我想拔掉副屏（或换小显示器）后重开，窗口保留我调的尺寸、位置自动挪到主屏居中，以便现场不因显示器变化而丢尺寸或飞出可见区域。
13. 作为用户，我想多显示器负坐标与部分越界的窗口位置照常恢复，以便多屏布局不被误判为失效。
14. 作为用户，我想会话执行中重启后，打开的是记住的会话、后台消费与执行恢复行为照旧，以便本 feature 只改变「回到哪里看」，不改变「工作是否继续」。
15. 作为用户，我想现场文件损坏时应用照常启动（当未配置处理），以便一个坏文件不挡住整个应用。
16. 作为用户，我想拖动/缩放窗口时写盘被合并（防抖），以便磁盘不被高频小块写打扰，退出时未落盘的变化也会被刷出。

## Implementation Decisions

- **现场形状**：一份语义一份文件——`{ 窗口 bounds(x/y/width/height)、maximized、工作台目标、视图 }`。工作台目标沿用现有联合类型语义（某会话 id，或新建草稿 + 项目 id）；视图为现有顶层二值（工作区/设置）。两字段独立：设置页下目标仍是最后打开的工作台目标。
- **载体**：主进程新的 launch-state store，单个 JSON 文件（`launch-state.json`），落统一数据目录（尊重 `CODEXLIKE_HOME`），复用现有 JSON 读写基建（ENOENT→未配置态、损坏容错）。选 JSON 而非 SQLite 同库：建窗前消费、非会话数据、与会话库生命周期无关；时序与主题设置完全同构（whenReady 内先读现场、再建窗）。
- **窗口恢复**：BrowserWindow 创建时按现场给 bounds；maximized 为真时先按正常态 bounds 建窗再 maximize。无现场或失效时维持现有硬编码默认。
- **显示器校验**：恢复 bounds 与所有现存显示器可见工作区均无交集才判失效；失效则保留尺寸、位置改主屏居中。部分越界不修正（交给系统），负坐标合法。尺寸小于最小可用值时收紧。
- **保存路径分工**：窗口事件（move/resize 结束、maximize/unmaximize）由主进程监听，防抖合并落盘；工作台目标与视图切换是低频事件，渲染层经 IPC 上报后即时落盘。退出保存屏障在退出前 flush 防抖中的未落盘写。
- **冷启动恢复**：现有渲染层冷启动逻辑的第一优先级从「内存中的活动会话」换成「启动现场的工作台目标」，回退链保持不变（目标失效→排序最前的未归档会话→新建草稿入口）；顶层视图初始值取启动现场。
- **IPC 契约**：新增启动现场的读取（渲染层启动查询）与上报（目标/视图变更）通道；不改动现有窗口控制通道语义。
- **命名**：代码中 `WindowState` 已被运行时最大化标志占用，新类型与通道命名须避开该词，采用 launch state 语义。
- **不动的东西**：`workbench_state` 表的草稿/偏好/阅读位置机制、输入队列重启自动继续、执行中会话恢复行为全部原样。

## Testing Decisions

- 只测外部行为（重启后可见的窗口状态与打开的内容），不测实现细节。
- **E2E（主接缝，现有）**：真实 Electron 退出重开（先例：theme、exit-recovery、input-queue-restart），`launchApp({ homeDir })` 隔离。场景：预写现场文件→启动→从渲染层读窗口位置/尺寸/最大化断言已应用；真实 UI 切会话、切视图、进草稿→退出重开→断言回到该目标与视图；记住的会话失效→回退最近未归档；归档会话恢复；无文件首启默认行为；kill 进程后重开现场仍在。
- **窗口 move/resize 的保存链路不放 E2E**（CI 无显示器环境驱动不可靠）：由单测覆盖主进程监听与防抖落盘，且目标/视图保存的真实 E2E 已覆盖同一条「渲染层→主进程→文件」通路。
- **单测（现有接缝，desktop 测试目录）**：launch-state store 读写往返、损坏回退（形态照现有设置 store 单测先例）；显示器校验纯函数（无交集判定、尺寸收紧、居中回退）；防抖合并与退出 flush。
- E2E 需注意 localStorage 主题镜像之类的跨运行残留问题在隔离 homeDir 下的表现（theme E2E 已有先例处理）。

## Out of Scope

- 全屏状态的保存与恢复（现状无全屏支持）。
- 多窗口（现状单窗口，弹窗一律外部浏览器）。
- 执行中会话的重启恢复、输入队列自动继续（既有机制，行为不变）。
- 侧栏宽度、折叠开合等更细粒度 UI 状态（现状本就不落盘）。
- `workbench_state` 已覆盖的草稿文本、发送偏好、阅读位置（不动）。
