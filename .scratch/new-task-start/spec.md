# Spec: 新建任务居中起点式（ADR 0026）

Status: ready-for-agent

原「新建会话页」重构。需求共识经三轮访谈确认（2026-11-18），原型三变体对比后变体 A「决策台」定稿并按用户反馈修订四项（分支 prototype/new-task-start，42f9d95）。决策记录见 `docs/adr/0026-new-task-centered-start.md`；术语见 GLOSSARY「新建任务」词条。

## Problem Statement

新建任务页此前复用正式任务的聊天布局：空消息流 + 底部输入卡 + 一行小字工作区信息。用户面对近乎空白的页面缺乏「新建时刻」的起点感；工作区、本地/Worktree 模式这些新建时的高决策项挤在一行小字与输入卡工具栏里，信息架构错位。侧栏顶栏「+」菜单按项目数膨胀出多个选项，而归属决定其实可以在页面内做。

## Solution

居中起点式专属布局（变体 A「决策台」）：内容列 800px 垂直居中、纯起点留白；标题行右侧「项目」选择器（选某项目或「不选项目（独立任务）」）；工作区单独成卡（项目任务：路径 + 本地/Worktree 切换；独立任务：专用目录/选择已有目录/回退）；审批模式、模型（Profile·模型）、思考档位一级呈现；技能不入一级——输入框 `$` 直调随首条消息生效；发送按钮为 composer 同款圆形上箭头图标。顶栏「+」菜单简化为单一「新建任务」按钮。文案统一「新建任务」心智，用户可见面不出现「草稿」。

## User Stories

1. 作为用户，我想从侧栏顶栏「+」一键进入新建任务页，不再从多选项菜单里挑，这样新建路径更短。
2. 作为用户，我想在新建页标题行右侧选择任务归属的项目或不选，这样归属决定在页面内做出并可随时修改。
3. 作为用户，选择项目后我想看到项目目录并可切换本地/Worktree 模式，切 Worktree 时明示「来源目录，发送后使用隔离工作区」，这样任务在哪跑一目了然。
4. 作为用户，不选项目时我想使用应用管理的专用持久目录，或选择已有目录、并可回退到专用目录，这样独立任务的起点灵活可控。
5. 作为用户，切换项目归属时我想保留各入口已持久化的草稿内容（切到哪个入口就恢复哪个入口的文字与设置），这样切换不丢工作。
6. 作为用户，我想在输入卡上方一级调整审批模式，切到「完全访问」时弹出风险确认，这样权限档位在发送前定好。
7. 作为用户，我想一级选择模型（Profile·模型 二元组）与思考档位，这样「由谁跑、跑多深」在新建时刻就定。
8. 作为用户，我想在输入框用 `$` 直接调用技能（随首条消息生效），决策区不再有技能配置项，placeholder 提示 `$ 技能` 的存在。
9. 作为用户，发送按钮是和任务窗口一致的圆形上箭头图标，空输入时禁用，这样视觉与行为都一致。
10. 作为用户，没配任何 Provider Profile 时，新建页整体呈现配置引导卡（品牌语 + 一键去设置），而不是残缺的表单。
11. 作为用户，发送首条消息成功后界面立即切入任务视图（即时硬切），创建失败时输入与设置保留、显示中文错误可重试。
12. 作为用户，从项目组头/独立组头悬停「+」进入时直达对应归属的新建页（预选语境），原语境入口保留。
13. 作为用户，`/new` 斜杠命令照旧进入新建任务页（沿用当前管理归属）。
14. 作为用户，冷启动时按启动现场恢复到新建任务页（target kind=new）。
15. 作为用户，任务并发满员时首条发送照旧进入任务排队（排队中状态条与徽章），新布局不改变排队语义。
16. 作为用户，窗口收窄时决策项与长路径换行平铺（不收纳、不溢出、不重叠），超长路径完整可读。
17. 作为用户，light/dark 双主题下新建页协调一致（走语义 token）。
18. 作为用户，标题栏在新建态保持品牌回退，项目身份由工作区一级项承载，不重复标识。
19. 作为用户，新建页所有用户可见文案以「新建任务」心智书写（如「发送第一条消息后创建任务」），不出现「草稿」。
20. 作为用户，等待用户交互期间/创建中的禁用语义与现状一致（复用现有 busy/disabled 规则）。

## Implementation Decisions

- **WorkspacePage 草稿态分支整体替换**为新建任务组件树（居中起点式）；正式任务的 MessageComposer、消息流布局零波及。
- **新建态专属输入卡壳**：卡片壳为新设计（更大输入区、图标发送按钮），内部复用 composer 子件——审批/模型/思考选择器、`/`·`@`·`$` 菜单、发送逻辑与现有 props 接线。
- **项目归属选择器**：页面内选项目或不选。切换归属等价于「切换入口」：加载对应入口的持久草稿（`["new", projectId]` / `["new", null]`），持久化模型一寸不动；切换时重置独立任务的已选目录状态。
- **工作区行形态由归属驱动**：项目任务 → 项目目录 + 本地/Worktree 切换（Worktree 文案明示来源目录语义）；独立任务 → 专用持久目录（「发送第一条消息后分配」）+「选择已有目录」（原生目录对话框）+ 选中后「使用专用目录」回退。域语义红线：独立任务无 Worktree 选项；工作区首次执行后固定。
- **TaskSidebar 顶栏「+」菜单退役**为单一「新建任务」按钮（直达独立入口草稿）；项目组头/独立组头悬停「+」保留为带语境直达。入口仍收敛到同一新建页。
- **无 Provider Profile**：新建页整体替换为配置引导卡，主按钮直达设置页（复用现有 onOpenSettings）。
- **发送按钮**：与 MessageComposer 同款圆形 accent 上箭头图标按钮；空输入禁用。
- **发送后过渡**：成功即时硬切任务视图（无动画）；失败回退语义照旧（`draft-error` 中文提示、输入与设置保留）。
- **文案**：新建页全量按「新建任务」心智重写；内部标识符（`NewTaskDraft`、`draftProjectId`）与 `draft-*` testid 不改（域语义层不动）。
- **域语义不变清单**：首条发送才创建任务、requestId 幂等与失败补偿、草稿按入口持久化、独立入口无 Worktree、任务排队语义、冷启动恢复。

## Testing Decisions

- 只测外部行为（呈现结构、交互效果、IPC 契约），不测实现细节；断言用 testid 与可见文案。
- **Seam 全部沿用既有形态，无新 seam**：
  1. **新建任务组件单测**（ui 包，新测试文件；先例：`task-sidebar-ui`、`workspace-opener-ui`）：归属选择器切换驱动工作区行形态、审批循环与 full-access 确认弹层、模型/思考选择、无 Profile 空态引导卡、发送按钮禁用与图标形态、技能提示在 placeholder。
  2. **侧栏单测扩展**（`task-sidebar-ui`）：顶栏「+」菜单退役为单按钮、直达回调；组头「+」语境直达保留。
  3. **e2e 实跑**（desktop 包）：`entry-consistency`（新入口语义重写断言）、`projects-sidebar`、`persistent-workbench`（切归属=切入口草稿）、worktree 首发流程场景——AGENTS.md 规矩：改 e2e 交互面必实跑，单测全绿不代表 e2e 可用。
- 视觉走查（非自动化）：双主题 × 长路径 × 窄窗，对照原型定稿变体。

## Out of Scope

- 正式任务页布局与 MessageComposer 内部改动。
- 新建页放最近任务/示例提示词（ADR 0026 明确拒绝）。
- 向导分步式流程。
- 域语义变更（首条创建、幂等、按入口持久化模型、排队）。
- 内部标识符与 `draft-*` testid 改名。
- 转场动画（即时硬切，后续真用着别扭再议）。
