# 会话工作台重构规格

**Status:** ready-for-agent

用户已确认功能范围、测试方式及九张任务票的粒度和依赖。本规格是实施与验收依据；[设计记录](decisions.md) 保留访谈背景，[ADR 0010](../../docs/adr/0010-session-workbench-project-membership-and-workspace.md) 记录关键取舍。发布规格不代表业务实现已经开始。

## Problem Statement

现有会话管理把项目当作目录派生的分组，新建需要反复选择目录，不支持独立于会话存在的项目，也不能表达不归属项目的长期会话。用户需要类似桌面编码助手的常驻工作台，而不是围绕当前单次任务组织的界面。

现有执行虽在后台继续，界面却没有完整保留后台正文增量和工具现场；切回运行中会话可能暂缺已经发生的输出。草稿、阅读位置、设置记忆与退出恢复也没有形成统一体验。侧栏按钮和斜杠命令存在行为差异，Worktree 的执行目录、来源目录与项目归属混在一起。

本次允许整体重构会话模型、持久化、宿主接口、状态管理和界面，不兼容旧会话管理数据；不以旧实现的结构限制目标体验。

## Solution

采用常驻侧栏与单会话主区：侧栏分别组织独立会话和独立存在的项目，项目内直接新建会话，全局入口新建独立会话。项目归属是管理关系，工作区是执行目录，两者不再互相推导。

新建先进入草稿，首次发送才创建正式会话及必要目录。查看与执行完全分离，多个会话可并行，切换后现场完整，草稿、阅读位置和会话设置独立持久保存。通过置顶、最近使用、跨项目搜索和归档管理历史。

退出应用前提示未完成任务；确认退出会中断执行，重启恢复工作现场而不重放工具。归档、项目移除和归属调整不删除用户磁盘文件，也不暗中切换执行目录。

## User Stories

1. 作为用户，我希望添加一个本机目录为项目，以便以后直接在项目内开始任务。
2. 作为用户，我希望空项目仍保留在侧栏，以便先建立项目再开展工作。
3. 作为用户，我希望普通非 Git 目录也能作为项目，以便处理不限于代码仓库的任务。
4. 作为用户，我希望每个项目旁都有新建入口，以便不重复选择工作目录。
5. 作为用户，我希望全局入口能直接新建独立会话，以便不先创建项目就开始对话。
6. 作为用户，我希望独立会话在侧栏单独组织，以便不会混入某个自动生成的默认项目。
7. 作为用户，我希望独立会话与项目会话具有同样的历史和整理能力，以便独立会话不是临时内容。
8. 作为用户，我希望新建先显示草稿页，以便准备输入和设置而不产生空历史。
9. 作为用户，我希望每个项目及独立入口分别保留一份新会话草稿，以便临时切换不丢输入。
10. 作为用户，我希望首次发送才创建正式会话，以便取消准备不会留下空会话。
11. 作为用户，我希望会话自动命名且可重命名，以便快速识别不同任务。
12. 作为用户，我希望连续点击发送不会重复创建会话，以便一次意图只产生一个任务。
13. 作为用户，我希望创建失败后能保留输入并重试，以便不会丢草稿或把失败显示为成功。
14. 作为用户，我希望独立会话默认有专用持久目录，以便不选目录也能开始，并且文件位置明确。
15. 作为用户，我希望独立会话首次发送前可指定本机目录，以便处理已有文件但不必把它加入项目。
16. 作为用户，我希望界面显示实际工作区，以便知道文件和命令在哪个目录执行。
17. 作为用户，我希望项目会话默认本地模式，以便无需每次回答模式选择对话框。
18. 作为用户，我希望首次发送前可以选择 Worktree，以便需要时使用隔离目录和分支。
19. 作为用户，我希望首次发送前不创建 Worktree，以便未启动任务不产生额外工作副本。
20. 作为用户，我希望同目录并行会话有共享文件提示，以便理解冲突风险而不被全面禁止并行。
21. 作为用户，我希望执行开始后工作区固定，以便历史上下文不会对应到另一个目录。
22. 作为用户，我希望多个会话可以同时执行，以便在等待一个任务时处理另一个任务。
23. 作为用户，我希望切换会话不停止任务或取消等待，以便自由查看其他内容。
24. 作为用户，我希望切回仍在运行的会话立即看到完整正文和工具记录，以便无需等最终结果才能了解进展。
25. 作为用户，我希望等待审批或问答的会话明确提示，以便及时处理而不会错答其他会话。
26. 作为用户，我希望完成未查看、失败和中断状态可辨认，以便知道接下来需要做什么。
27. 作为用户，我希望每个会话保存自己的输入和问答草稿，以便切换和重启后继续准备。
28. 作为用户，我希望每个会话恢复阅读位置，以便不用在长历史中重新寻找内容。
29. 作为用户，我希望模型、思考档位和权限按会话记忆，以便切换任务不会串用配置。
30. 作为用户，我希望调整设置仅影响下次发送，以便不会改变已经开始的执行。
31. 作为用户，我希望新会话使用应用默认模型及思考档位，并从 ask 权限开始，以便不会继承另一个会话的完全访问权限。
32. 作为用户，我希望完全访问仍需显式开启，以便授权边界清晰。
33. 作为用户，我希望项目可折叠、会话可置顶，以便常用内容容易找到。
34. 作为用户，我希望非置顶会话按最近使用排列，以便快速返回最近处理的任务。
35. 作为用户，我希望后台逐条输出不改变列表顺序，以便点击目标不会不断移动。
36. 作为用户，我希望跨项目搜索标题和消息正文，以便找回独立会话和项目会话中的内容。
37. 作为用户，我希望选择是否搜索归档会话，以便既能精简列表又能查全历史。
38. 作为用户，我希望归档会话可查看和恢复，以便整理历史不等于丢失任务。
39. 作为用户，我希望归档不删除 Worktree，以便尚未收回的成果仍在磁盘上。
40. 作为用户，我希望在满足目录约束时把独立会话移入项目，以便调整组织方式。
41. 作为用户，我希望把项目会话移出为独立会话，以便取消归属而不搬动文件或重写历史。
42. 作为用户，我希望 Worktree 会话移出后仍保留来源，以便以后能正确移回来源项目。
43. 作为用户，我希望移除项目前得到明确确认，以便理解其所属会话记录也会被移除。
44. 作为用户，我希望移除项目保留磁盘文件和无归属的同目录会话，以便管理操作不会误删工作成果或其他记录。
45. 作为用户，我希望执行或等待回应时不能被直接归档、调整归属或移除项目，以便先明确停止再整理。
46. 作为用户，我希望应用不再按数量自动删除 Worktree，以便未处理的成果不会因新建其他会话消失。
47. 作为用户，我希望有任务时退出先提示且可以取消，以便不会无意中断工作。
48. 作为用户，我希望重启恢复项目、会话、历史、草稿、阅读位置和设置，以便继续工作。
49. 作为用户，我希望重启后未完成任务显示为已中断，以便由我决定是否继续，而不是自动重跑命令。
50. 作为用户，我希望按钮、快捷入口和斜杠命令遵循相同规则，以便入口不同不产生不同结果。

## Implementation Decisions

### 领域与职责

- 项目成为独立持久实体；会话显式记录可空的项目归属。独立会话不是伪造的默认项目，也不因执行目录匹配某项目而自动归属。
- 会话承载可多次继续的历史与偏好；一次执行的运行状态不代表会话生命周期。查看状态、会话归属、执行状态分别表达。
- 工作区在首次执行开始后固定；Worktree 来源信息独立于当前项目归属保存。目录相等判断遵循实际文件系统路径语义，不以显示名称或简单字符串前缀判断归属。
- 项目与会话管理模块统一承载创建、归属、整理和运行保护规则；宿主公开接口是业务测试的主要 seam。renderer 不独自承担授权或并发保护。
- 保留 Agent Core 与 Electron 解耦、SQLite 持久化及类型化 IPC。可重做其会话管理接口，不无故替换 provider、主题、资源快照或其他无关能力。

### 创建、目录与失败一致性

- 新建草稿按项目及独立入口区分；首次发送前可调整工作区模式和发送设置。正式会话与必要工作目录在首次发送时建立。
- 一次首次发送只创建一个正式会话；创建失败保留可重试草稿，不显示虚假的成功会话。对已创建资源的失败处理不得扩大为清理用户原目录或已有成果。
- 独立会话默认使用应用管理的专用持久目录，首次发送时创建；可提前改为用户指定目录。首版独立入口不直接创建 Worktree。
- 项目会话默认本地模式，可在首次发送前选择 Worktree；非 Git 目录可使用本地模式，无法创建 Worktree 时给出明确错误。
- 同目录本地会话并行提示文件共享风险，但不全局锁死并行。

### 运行现场、发送设置与持久工作现场

- 运行现场通过统一的会话视图接口提供。无论 renderer 当前查看哪里，都能重新取得完整正文增量、工具卡片和待处理交互；初始现场与后续事件衔接不得漏事件或重复显示。
- 不把所有后台增量只保存在当前页面状态里；会话标识与执行标识应足以隔离旧执行迟到事件和其他会话事件。
- 普通输入、新会话输入、问答草稿、阅读位置和会话偏好持久保存。历史中的记录、运行期现场和下一次发送的草稿不互相覆盖。
- 模型选择、思考档位和审批模式按会话记忆；每次发送确定本次执行的设置，后续编辑只影响下一次发送。子代理及待处理交互沿用所属执行的语义。
- 新会话使用应用默认模型及思考档位，审批模式为 `ask`；`full-access` 仍需显式开启和风险确认。恢复已明确设置的会话偏好不等于从其他会话继承权限，也不构成对某个待审批操作的永久授权。
- 本次不改变现有思考内容的历史持久化约定，不以恢复工作现场为由扩大敏感或运行期内容的落盘范围。

### 侧栏、搜索与整理

- 使用独立会话分区及可折叠项目分区；每区内支持会话置顶和最近使用排序。后台逐条流式输出不是最近使用排序的触发源。
- 运行、等待用户处理、完成未查看、失败和中断可区分；已读状态与执行状态分别表达，切换查看不会终止执行。
- 搜索覆盖标题与消息正文，跨项目与独立会话，归档内容通过开关纳入；结果的项目归属和实际会话保持一致。
- 归档隐藏日常列表但保留历史和文件，可查看及恢复；首版不新增永久删除单条会话。
- 归属调整仅在没有执行且没有等待回应时允许。独立会话只移入目录匹配的项目；项目会话可移出；Worktree 会话只能移回来源项目，且保留来源信息。
- 移除项目明确确认后移除项目及其所属会话记录；按显式归属确定影响范围，不能按目录扫除独立会话。项目目录与 Worktree 文件保留。
- 执行或等待用户回应时先停止才能归档、调整归属或移除；宿主在实际执行操作时复查，防止 UI 检查后状态发生变化。
- 取消按数量自动删除 Worktree，磁盘清理与会话整理分开；不在本次扩展完整磁盘清理产品。

### 退出与入口一致性

- 真正退出应用前提示未完成执行或等待；取消退出不取消任务，确认退出才停止任务及未完成交互。
- 重启恢复持久工作现场；未完成执行标记为中断，旧的等待请求不可当作可继续执行的有效授权。不得自动重放工具或续跑；用户可以显式发起后续发送。
- 按钮、快捷入口和斜杠命令调用同一管理规则。全局新建是独立会话；项目入口使用其项目；会话内新建遵循当前管理归属，不把 Worktree 执行路径派生为新项目。
- 使用新模型而不兼容旧会话管理数据。实施时明确新数据初始化与旧数据隔离方式，不要求迁移，也不以此授权自动删除用户代码、Worktree 或其他无关数据。

## Testing Decisions

### 主验收 seam

优先从宿主公开接口测试项目、会话、草稿、整理与退出行为，结合真实 Core、SQLite 和临时目录；模型使用可控的脚本或本地 HTTP/SSE adapter。测试关注可观察结果、错误和副作用，不锁定私有 SQL 布局或 React 内部状态。

既有 IPC 测试先例通过模拟 Electron 注册器调用真实 handler，能验证业务集成，但不等价于跨进程 IPC。因此关键路径再用真实 Electron、preload、IPC、React 和 SQLite 串联，仅替换外部模型。现有会话恢复等价性、SQLite 重开、用户交互 IPC、慢速 SSE E2E 和打包冷启动测试可复用，不另搭平行测试框架。

### 必测场景

- 空项目持久存在、项目与独立入口新建、首次发送延迟创建，以及双击发送、目录或 Worktree 创建失败重试。
- 在模型仍未结束时 A→B→A，正文、工具起止、待处理审批与问答完整，跨会话隔离；不能只在最终结果补全后断言。
- 使用可控事件闸门验证现场取得与增量衔接、停止与迟到事件、整理与执行启动竞态。
- 真实关闭并重开文件 SQLite 和应用进程，验证草稿、阅读位置、模型和权限记忆；不能以同一缓存实例或 renderer reload 替代应用重启。
- 设置修改只影响下一次发送，新会话不继承完全访问；已有审批拒绝不落盘、权限边界、无永久授权记忆保持。
- Worktree 隔离及来源保留、同目录共享提示、非 Git 失败、归档或移除不删文件、数量增长不触发旧自动清理。
- 独立会话与项目会话搜索、归档开关、置顶与排序；后台输出不改变列表位置。
- 项目移除不删除同目录独立会话；运行或等待时拒绝整理操作；项目移除确认取消时不产生副作用。
- 退出确认取消则继续，确认退出则中断，重启无模型自动请求及工具重放，旧等待交互不可直接继续。
- 用户真实点击、滚动和切换由 Electron E2E 验证；静态渲染或纯函数测试不作为这些行为的替代。

### 回归与交付

每张任务票自带相应的集成与端到端测试。最后一票汇合验收而非集中补测，保留审批、用户交互、子代理、文件访问、主题、资源配置及模型协议等既有有效能力。

与目标冲突的旧断言应替换：权限调整对当前执行立即生效、重启草稿丢失、目录派生项目、超过数量自动清理 Worktree，以及旧库迁移要求，均不能继续用作新实现的验收目标。

测试、构建和打包使用仓库既有脚本，直接取得退出码，不接截断管道。Windows 为主要交付平台；检查构建、类型、单测、完整 E2E 和打包冷启动。实际运行的通过、失败、跳过必须分别记录，文档发布阶段不声称测试通过。

## Out of Scope

- 旧会话管理数据兼容与迁移。
- 多标签、多会话分屏、多级分类、标签或文件夹体系。
- 永久删除单条会话。
- 独立会话入口直接创建 Worktree。
- 退出应用后的常驻执行、自动续跑、完整执行检查点恢复。
- 完整磁盘清理管理产品，以及自动删除项目目录或 Worktree 文件。
- 无关的数据库、provider 协议、主题或 Agent Core 架构替换。
