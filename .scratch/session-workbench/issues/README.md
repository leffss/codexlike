## 推进方式

1. 当前只有 01 无阻塞，可以先实施。
2. 01 完成后，02、03、04、05 可分别推进；共用其稳定的项目归属、首次发送和执行状态契约，按实际文件改动面协调并行。
3. 05 完成解锁 06；04 和 05 完成解锁 07；02 和 03 完成解锁 08。
4. 02–08 全部完成后执行 09，验证组合路径、入口一致性与真实打包产物。

每张票是贯穿存储、宿主公开接口、界面与测试的纵向切片；不得把测试集中推迟到 09。02、03、04、05 并列不代表可以各自发明不兼容的会话管理接口。

工作前读取对应票及规格，按阻塞关系开始；按实际结果更新票状态与验收项。新模型不兼容旧会话管理数据，但所有工作继续遵守用户文件保留、权限保护以及提交授权边界。
