# 01: 建立项目与独立会话的新建闭环

**What to build:** 用户可以添加并保留空项目，在项目内或全局独立入口准备新会话草稿，首次发送才生成正式会话并执行。独立会话默认使用专用持久目录，也可指定目录；项目归属与实际工作区分离。该票贯穿持久化、宿主公开接口、侧栏、输入区和测试，形成后续任务可复用的新模型与创建契约。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Spec:** [会话工作台重构规格](../spec.md)

## Acceptance criteria

- [ ] 项目是独立持久实体，添加本机目录后即显示；没有会话也保留，重新打开后仍存在。普通非 Git 目录可用。
- [ ] 会话项目归属可空；独立会话单列分区，不创建虚假的默认项目，不根据目录自动加入项目。
- [ ] 全局新建进入独立会话草稿；项目旁新建进入该项目草稿，项目内不重复要求选择目录。
- [ ] 每个项目及独立入口各有一份新会话草稿；切换查看已有会话不丢失当前进程中的输入。跨重启持久化由票 03 完成。
- [ ] 首次发送前不创建正式会话或专用目录，不产生空历史；首次发送完成创建后调用正常执行路径，首条消息与会话对应。
- [ ] 独立会话默认在首次发送时分配应用管理的专用持久目录；首次发送前可以改选已有目录，选目录不创建项目。
- [ ] 项目内默认直接使用项目目录；本票交付本地模式，Worktree 延迟创建在票 04 接入同一首次发送契约。
- [ ] 界面明确展示实际工作区；首次执行开始后不允许更换该会话工作区。
- [ ] 会话自动命名并可手动重命名，独立与项目会话一致；标题更改持久保存。
- [ ] 首次发送有去重和一致性保护，连续触发不会生成重复会话或重复执行首条消息。
- [ ] 创建目录或建立会话失败时给出可理解的错误，保留可重试草稿，不把失败显示为成功或留下额外空会话；不清理用户已有目录和成果。
- [ ] 建立后续共用的稳定会话标识、可空项目归属、工作区与来源字段、执行中及等待用户状态契约。后续票不需要用路径重新推导归属或用当前页面判断执行状态。
- [ ] 初始新会话使用应用默认模型和思考档位、审批模式 `ask`，不从其他会话复制完全访问权限。
- [ ] 新会话管理模型不兼容旧管理数据；明确初始化或数据隔离方式，不要求迁移，也不自动删除旧文件、用户代码或 Worktree。
- [ ] 不把本票变成全仓机械重写：保留 SQLite、类型化 IPC、Core 与 Electron 解耦以及无关既有能力，完成从创建到执行的可用切片。

## Verification

- [ ] 通过宿主公开接口与真实 SQLite、临时目录验证空项目、可空归属、首次发送、路径约束、失败重试和重复触发；断言外部行为而非私有存储结构。
- [ ] 真实 Electron E2E 完成添加空项目、项目内首次发送、独立首次发送、切换两类会话；模型使用本地可控服务。
- [ ] 用一个与项目目录相同但无项目归属的独立会话证明不会被自动分组。
- [ ] 交付说明记录新接口的输入、失败语义和执行保护信息，供票 02–05 共用；不凭空新增多个等价管理入口。

## Scope boundary

Worktree、完整运行现场、跨重启草稿与设置、整理搜索和退出流程由后续票完成；本票必须提供可工作的本地创建与发送闭环，而不是仅交付 schema 或空界面。
