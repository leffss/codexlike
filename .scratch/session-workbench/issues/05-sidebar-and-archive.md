# 05: 完成侧栏整理与归档恢复

**What to build:** 用户通过可折叠项目、独立会话分区、会话置顶和最近使用顺序整理工作台；会话可以归档、查看及恢复，运行或等待回应时先停止。后台输出不使列表跳动，不同入口遵循相同整理规则。

**Blocked by:** 01 — 建立项目与独立会话的新建闭环。

**Status:** ready-for-agent

**Spec:** [会话工作台重构规格](../spec.md)

## Acceptance criteria

- [ ] 常驻侧栏分别显示独立会话和各项目会话，主区同一时刻查看一个会话，不引入标签页或分屏。
- [ ] 项目可折叠，独立和项目会话均可置顶；整理状态保存后重开仍可恢复，不改变项目归属或工作区。
- [ ] 非置顶会话按用户最近使用排序，后台正文增量、工具事件或其他刷新不驱动列表反复重排。
- [ ] 新建、重命名、归档、恢复后的列表一致反映持久数据，不依靠旧的目录聚合键。
- [ ] 归档仅从日常列表隐藏，历史和 Worktree 保留；提供可发现的归档查看与恢复入口，不依赖尚未完成的搜索票。
- [ ] 恢复后回到其原显式归属的分区；原本独立的会话不会因目录匹配被自动塞入项目。
- [ ] 无论从侧栏、会话内操作或现有斜杠命令归档，当前选中会话和主区处理一致，不出现一处留在归档会话、一处跳走的冲突。
- [ ] 执行中或等待用户回应的会话不能直接归档，提示先停止；取消或拒绝操作不会中断任务或更改记录。
- [ ] 宿主实际执行归档时复查活动状态，避免列表状态过时导致正在运行的会话被归档。使用票 01 的活动状态契约，不依赖票 02 的展示实现。
- [ ] 归档和恢复不删除文件、不调用 Worktree 自动清理，不新增永久删除单条会话。
- [ ] 界面整理操作与用户交互入口兼容，不让项目折叠或会话置顶取消待处理请求。

## Verification

- [ ] 真实 SQLite 与公开接口验证置顶、归档、恢复、归属保留、重开后的状态及活动时拒绝整理。
- [ ] 用可控后台输出验证最近使用排序稳定；不把记录更新时间误当成用户最近使用时间。
- [ ] 真实 Electron E2E 操作折叠、置顶、归档查看与恢复，并核对当前主区与侧栏入口的一致性。
- [ ] 以临时文件标记验证归档后项目目录和 Worktree 文件不变；项目移除的文件保护由票 07 验证。

## Scope boundary

不依赖票 02 的完整运行现场，只复用票 01 已存在的活动判断；跨项目搜索由票 06 接入本票的归档契约。
