# 04: 接入延迟创建的 Worktree 与共享目录提示

**What to build:** 项目内新会话默认直接在项目目录工作，用户可在首次发送前选择 Worktree，发送时才创建独立目录和分支。同目录本地会话可以并行，但明确提示共享文件；Worktree 来源长期保留且不按数量自动清理。

**Blocked by:** 01 — 建立项目与独立会话的新建闭环。

**Status:** ready-for-agent

**Spec:** [会话工作台重构规格](../spec.md)

## Acceptance criteria

- [ ] 项目新会话草稿默认本地模式，在输入区提供明确的 Worktree 选择，不强制弹出模式选择对话框。
- [ ] 首次发送前只调整草稿，不创建 Worktree、分支或正式会话；发送后才建立所需资源并开始任务。
- [ ] Worktree 创建走票 01 的统一首次发送契约，正式会话明确归属来源项目，实际工作区指向隔离目录。
- [ ] 来源目录信息独立保存，不依赖侧栏派生分组或可被清理的临时记录；支持后续会话移出项目后仍识别来源。
- [ ] Worktree 使用独立目录及分支，文件和终端操作使用正确工作区；界面显示本地或 Worktree 及实际目录。
- [ ] 非 Git 项目本地模式正常可用；无法创建 Worktree 时给出清晰反馈，保留草稿且不留下虚假成功会话。
- [ ] 连续发送与失败重试不会重复创建 Worktree 或正式会话；对失败资源的处理仅限本次可证明新建且安全清理的资源，不删除用户已有目录或成果。
- [ ] 独立会话入口不直接提供 Worktree 创建；首次执行开始后不能通过模式选择更换现有会话工作区。
- [ ] 已有其他本地会话在同一目录执行时给出共享文件风险提示，允许用户继续，不设置一刀切的项目执行锁。
- [ ] 共享目录判断基于实际工作区而非仅项目名称或项目归属，避免同目录独立会话被忽略；不同 Worktree 不误报为同一执行目录。
- [ ] 删除按数量自动清理 Worktree 的行为及触发入口，新建更多会话不会自动删除较早的副本或分支成果。
- [ ] 已有显式清理能力如需保留，仍与会话整理分离；本票不新增完整磁盘清理产品，不把归档或项目移除连接到磁盘清理。

## Verification

- [ ] 使用真实临时 Git 仓库验证目录与分支隔离、首次发送前无副本、发送后正确工作区及持久来源。
- [ ] 验证非 Git 失败、创建中途失败、重复发送与重试，不产生重复或空会话，不删用户目录。
- [ ] 覆盖旧数量阈值以上的新建场景，断言早期 Worktree 文件仍存在且未触发自动清理。
- [ ] 真实 Electron E2E 完成模式选择、首次发送、共享目录提示与失败反馈。
- [ ] 保留 Worktree 文件复制边界和独立运行测试；移除与新设计冲突的自动删除旧断言。

## Scope boundary

本票提供可验证的 Worktree 创建与来源事实；归属移动和项目移除由票 07 使用这些事实实现。不要为等待票 07 而推迟本票创建闭环。
