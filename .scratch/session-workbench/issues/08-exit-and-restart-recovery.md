# 08: 完成退出确认与重启恢复

**What to build:** 用户真正退出应用时若有执行或待处理交互先得到提示；取消退出则工作继续，确认退出则任务中断。重启恢复项目、会话、历史、草稿、阅读位置和设置，不自动续跑或重放任何工具。

**Blocked by:** 02 — 切换会话时完整保留执行现场；03 — 持久保存草稿、阅读位置与会话设置。

**Status:** ready-for-agent

**Spec:** [会话工作台重构规格](../spec.md)

## Acceptance criteria

- [ ] 真正退出应用前检测所有项目及独立会话的未完成执行和待回应请求，不只检查当前选中会话。
- [ ] 存在未完成工作时先提示；用户取消退出后应用保留，任务和等待继续，不能在确认前先取消任务。
- [ ] 用户确认退出后停止主执行及所属子代理，取消未完成用户交互，并保存中断状态及已完成历史。
- [ ] 已准备的普通输入、新建草稿、问答草稿、阅读位置和会话偏好在受控退出前完成持久化；异步保存不能因为窗口销毁而静默丢失。
- [ ] 重新启动同一数据目录后恢复项目、独立会话、项目会话和既有历史，以及票 03 的持久工作现场。
- [ ] 上次未完成执行显示为已中断，不错误恢复为仍在运行或可继续等待的实时任务；用户可通过明确的后续发送继续处理。
- [ ] 重启本身不触发模型请求、不执行工具、不重放旧命令，也不把已完成工具当作待重试任务。
- [ ] 旧审批和问答保留历史及可用草稿信息，但失效请求不可提交为有效执行响应；不从旧审批形成永久授权。
- [ ] 进程异常结束后残留的执行中或等待记录，在下次启动也被归一为中断，不假装恢复执行检查点。
- [ ] 不同退出入口遵循同一确认与中断流程；不因后台会话、折叠项目或搜索页面而漏掉确认。
- [ ] 应用不引入真正退出后的后台常驻机制，操作系统或应用重开不能自动启动未完成任务。

## Verification

- [ ] 关闭并重新打开真实 SQLite 文件，验证中断状态、草稿与偏好；不能仅复用内存 store。
- [ ] 真实 Electron E2E 启动慢速执行与等待交互，分别验证取消退出、确认退出，以及使用同一数据目录的新进程启动。
- [ ] 本地模型服务记录请求计数，临时目录记录工具副作用，证明重启后既没有自动模型请求也没有工具重放。
- [ ] 覆盖独立会话与项目会话并行、后台等待、子代理联动及异常终止后重新打开。
- [ ] 用真实点击和滚动验证恢复阅读位置；静态渲染或 renderer reload 不能替代本票的进程重启测试。

## Scope boundary

本票只恢复持久工作现场，不恢复未完成执行上下文，不为强制终止时尚未写入的瞬时内容作不可能保证。所有已确认保存的历史与状态必须可靠读取并正确表示。
