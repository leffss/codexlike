# 03: 持久保存草稿、阅读位置与会话设置

**What to build:** 用户切换或重新打开应用后，每个正式会话及各新建入口恢复自己的草稿和阅读位置；模型、思考档位、审批模式按会话记忆，每次发送采用确定的设置，后续调整只影响下一次发送。

**Blocked by:** 01 — 建立项目与独立会话的新建闭环。

**Status:** completed

**Spec:** [会话工作台重构规格](../spec.md)

## Acceptance criteria

- [x] 每个项目的新会话草稿及独立入口的新会话草稿分别持久保存，切换与重启不丢失；未发送草稿不成为正式历史会话。
- [x] 正式会话的普通输入、尚未提交的问答草稿分别保存，不能被另一会话的输入、后台事件或首次发送草稿覆盖。
- [x] 每个正式会话保存并恢复阅读位置，长历史切换后回到原阅读上下文；不以无条件滚到最底部替代恢复。
- [x] 重启后恢复草稿和阅读位置采用持久记录，不依赖同一进程内缓存或单个组件实例。
- [x] 模型选择、思考档位和审批模式按会话独立记忆并持久保存，切换时不会套用另一个会话的参数。
- [x] 每次发送确定本次执行的设置；修改界面偏好只影响下次发送，不改变已经开始的主执行、其工具审批语义或所属子代理设置。
- [x] 新会话采用应用默认模型和思考档位，审批模式为 `ask`；不从最近会话继承 `full-access`。
- [x] 完全访问仍须显式开启并保留风险确认；持久化偏好不构成对某一待审批操作的永久授权。
- [x] 新建草稿成功发送后只消费对应草稿；创建失败保留输入与设置，不误清除其他项目或独立入口草稿。
- [x] 问答草稿与请求归属关联；恢复文本不把已中断或失效请求变成可继续执行的请求。票 08 接入完整退出恢复流程。
- [x] 宿主提供统一的持久工作现场读写接口，覆盖切换与退出前写入时序，避免旧异步保存覆盖更新内容。
- [x] 已保存的模型配置不可用时明确反馈，不无提示换成其他模型或伪装发送成功；不复制 provider 密钥作为会话内容。

### 公开接口及 08 接入契约

- 类型在 `agent-core/src/session/workbench-state.ts`。唯一持久现场 IPC 为 `workbench.read(target)` / `workbench.write(target, { revision, value })`；target 为 `{ kind: 'new', projectId: string | null }` 或 `{ kind: 'session', sessionId }`。value 保存普通文本、`preferences { providerProfileId, thinkingEffort, approvalMode }`、按请求 ID 的问答草稿、阅读位置、首次发送 requestId、可选 workspacePath/workspaceMode；不保存密钥、执行许可、思考正文或运行事件。
- 主进程同步 SQLite 提交后才应答；revision 单调递增，旧写返回 `{ accepted: false, entry }`。新建意图成功后更换 requestId，迟到旧意图即便带更大 revision 也不能复活。首次发送沿用 `sessions.start`，只消费对应入口，失败保留，正式会话继承该次明确设置；新草稿重新使用首个 Profile / auto / ask。
- renderer `WorkspaceState.flush(): Promise<void>` 等待所有目标的串行写队列，失败抛错并显示保存错误。每次编辑即排队，切新建入口及发送前等待屏障；迟到读取不覆盖已编辑输入。08 的退出握手须先阻止新编辑，再 await 此屏障并等待成功答复，之后才关闭窗口/数据库；本票未实现退出确认、运行中退出或自动续跑。
- 普通 `sessions.send` 可省略模型/思考设置以采用该会话持久偏好；显式参数仍兼容既有调用，末尾可传本次审批快照。页面在点击发送时捕获设置，Core 固定本轮模型、思考及审批（含所属子代理），后续编辑只影响下次发送。偏好保存不调用 markUsed，也不更新最近使用时间。模型引用失效明确报错，不换默认模型。
- 阅读位置在真实消息滚动容器恢复，等待历史装载；再次打开同一个会话亦不把临时空历史归零写回。问答草稿仅对应真实本会话请求；pending 才可编辑提交，取消/重启失效后以只读草稿展示，绝不凭草稿重建 pending 或授予执行许可。成功回答消费其草稿，现有 Core 负责终结重启残留请求。
