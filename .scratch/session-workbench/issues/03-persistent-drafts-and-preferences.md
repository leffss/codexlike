# 03: 持久保存草稿、阅读位置与会话设置

**What to build:** 用户切换或重新打开应用后，每个正式会话及各新建入口恢复自己的草稿和阅读位置；模型、思考档位、审批模式按会话记忆，每次发送采用确定的设置，后续调整只影响下一次发送。

**Blocked by:** 01 — 建立项目与独立会话的新建闭环。

**Status:** ready-for-agent

**Spec:** [会话工作台重构规格](../spec.md)

## Acceptance criteria

- [ ] 每个项目的新会话草稿及独立入口的新会话草稿分别持久保存，切换与重启不丢失；未发送草稿不成为正式历史会话。
- [ ] 正式会话的普通输入、尚未提交的问答草稿分别保存，不能被另一会话的输入、后台事件或首次发送草稿覆盖。
- [ ] 每个正式会话保存并恢复阅读位置，长历史切换后回到原阅读上下文；不以无条件滚到最底部替代恢复。
- [ ] 重启后恢复草稿和阅读位置采用持久记录，不依赖同一进程内缓存或单个组件实例。
- [ ] 模型选择、思考档位和审批模式按会话独立记忆并持久保存，切换时不会套用另一个会话的参数。
- [ ] 每次发送确定本次执行的设置；修改界面偏好只影响下次发送，不改变已经开始的主执行、其工具审批语义或所属子代理设置。
- [ ] 新会话采用应用默认模型和思考档位，审批模式为 `ask`；不从最近会话继承 `full-access`。
- [ ] 完全访问仍须显式开启并保留风险确认；持久化偏好不构成对某一待审批操作的永久授权。
- [ ] 新建草稿成功发送后只消费对应草稿；创建失败保留输入与设置，不误清除其他项目或独立入口草稿。
- [ ] 问答草稿与请求归属关联；恢复文本不把已中断或失效请求变成可继续执行的请求。票 08 接入完整退出恢复流程。
- [ ] 宿主提供统一的持久工作现场读写接口，覆盖切换与退出前写入时序，避免旧异步保存覆盖更新内容。
- [ ] 已保存的模型配置不可用时明确反馈，不无提示换成其他模型或伪装发送成功；不复制 provider 密钥作为会话内容。

## Verification

- [ ] 真实 SQLite 文件关闭重开后验证草稿、阅读位置和设置；不得用同一内存实例冒充重启持久性。
- [ ] 用可控模型记录实际请求参数，验证本次执行不受中途修改影响、下一次发送采用新值，多个会话互不污染。
- [ ] 真实 Electron E2E 验证输入、切换、滚动和空闲应用重启恢复；完整运行中退出场景由票 08 验收。
- [ ] 覆盖快速切换后的延迟保存、草稿发送失败与重试、旧问答草稿不可继续授权等边界。
- [ ] 将旧的全局设置串用、重启草稿丢失、权限中途立即改变当前执行等冲突断言改为本规格语义；保留审批拒绝和文件访问保护回归。

## Scope boundary

不恢复模型执行检查点，不重放旧交互。设置持久化与运行期现场独立落地，因此不依赖票 02；票 08 再联合验收二者。
