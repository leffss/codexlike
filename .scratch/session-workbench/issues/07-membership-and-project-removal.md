# 07: 安全调整归属与移除项目

**What to build:** 用户可以在目录约束允许时把会话移入或移出项目，也可确认移除项目及其所属会话记录；这些整理只影响应用中的管理关系，不移动文件、不改变分支、不重写历史或删除磁盘成果。

**Blocked by:** 04 — 接入延迟创建的 Worktree 与共享目录提示；05 — 完成侧栏整理与归档恢复。

**Status:** ready-for-agent

**Spec:** [会话工作台重构规格](../spec.md)

## Acceptance criteria

- [ ] 非执行中且无待回应请求的独立会话可移入工作区匹配的项目；不同目录的会话不能随意归入目标项目。
- [ ] 项目会话可移出成为独立会话，工作区、分支、历史和已有会话偏好保持不变；侧栏立即反映新归属。
- [ ] 目录匹配采用实际文件系统路径语义，不通过项目名称、字符串前缀或展示文本判断。
- [ ] Worktree 会话移出后仍保留来源目录信息，只能移回来源项目，不能把实际 Worktree 目录当成新项目自动创建。
- [ ] 项目移除前明确说明影响的是项目及其所属会话记录，并说明磁盘文件保留；取消确认无副作用。
- [ ] 确认移除按显式项目归属处理包含归档在内的所属会话；删除或清理相关应用内索引和项目草稿，避免导航或搜索悬挂记录，但不按目录连带处理其他会话。
- [ ] 使用相同目录的独立会话，以及已经移出项目的 Worktree 会话，不能因原项目被移除而被误删记录。
- [ ] 项目目录、用户文件、托管 Worktree 目录及已有成果均保留；不调用按数量自动清理或其他隐式磁盘删除。
- [ ] 任一所属会话正在执行或等待用户回应时，不允许直接移除项目；运行或等待中的会话也不能调整归属，必须先明确停止。
- [ ] 宿主在实际修改归属或移除时重新检查活动状态，和执行启动形成一致性保护；UI 上按钮禁用不是唯一防线。
- [ ] 整理失败有明确反馈，不能出现界面宣称成功而记录只改了一部分，或移除后仍可向已移除会话启动新执行。
- [ ] 在当前会话被移出或其项目被移除后，主区与侧栏选择保持一致，不保留指向已移除记录的可发送入口。
- [ ] 如票 06 搜索或票 03 偏好已接入，整理遵守其公开契约且不破坏数据；本票不因此添加它们为阻塞依赖，相关组合由票 09 汇合验证。

## Verification

- [ ] 使用真实 SQLite 和临时目录验证本地会话移入、移出、目录不匹配拒绝以及 Worktree 来源限制。
- [ ] 创建项目会话、归档会话、同目录独立会话、已移出的 Worktree 会话，移除项目后断言影响集合准确，所有磁盘标记文件仍存在。
- [ ] 用可控执行启动和用户交互等待验证整理竞态、运行中拒绝、确认取消与失败一致性。
- [ ] 真实 Electron E2E 完成移入、移出、移除取消和确认，验证提示、侧栏及主区结果；不读取组件私有状态代替操作。

## Scope boundary

不支持用归属调整搬运工作区，不实现跨项目任意拖放，不引入永久删除单条会话或磁盘清理工具。项目移除是已确认的应用记录移除，不是删除目录。
