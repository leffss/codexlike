# Spec: 子代理工作计划

Status: ready-for-agent

决策依据：ADR 0023（update_plan 下放子代理，计划卡常驻右栏详情底部）；修订 ADR 0016 的「仅主任务」边界。术语见 GLOSSARY「工作计划」「计划项」「子代理」「子代理记录」。

## Problem Statement

子代理的委派常常天然多步，过程记录已与主代理同密度落库（ADR 0021），但用户在右栏子代理详情里看不到子代理「打算做什么、做到第几步」——工作计划是主任务独占的能力（ADR 0016 当时明确排除子代理），多步委派的进度只能靠逐轮翻工具调用与正文来推断。

## Solution

下放工作计划能力：子代理获得与主任务同款的 update_plan 工具与使用策略，各自维护自己的计划（与主任务计划互不汇聚、互不可见）；每个子代理详情正文最下方常驻一张与主任务同款的进度折叠卡（ADR 0019 形态），运行中实时更新，完成后回看终态，中断后回看最后快照；子代理导出 Markdown 带工作计划终态段。

## User Stories

1. 作为用户，我想看到每个子代理自己的工作计划（打算做什么、做到第几步），以便不逐轮翻过程记录就能掌握子代理进度。
2. 作为用户，我想子代理计划卡与主任务计划卡同款同位语义（长条形进度折叠卡、百分比 + N/M 计数 + 当前/下一步预览），以便沿用既有心智模型、零学习成本。
3. 作为用户，我想轻点子代理计划卡展开完整计划清单（三态、完成项删除线），以便细看每一步内容。
4. 作为用户，我想子代理计划卡的开合状态按子代理各自记忆，以便切换子代理再回来不丢展开状态。
5. 作为用户，我想子代理运行中时计划卡随每次计划更新实时刷新，以便随时看到当前进行到哪一步、接下来做什么。
6. 作为用户，我想子代理完成后仍能在详情底部回看它的最终计划状态，以便检视「它当时计划做什么、最终做到哪」。
7. 作为用户，我想子代理被中断后仍能回看最后一次计划快照，以便判断中断时进行到哪一步、还剩什么没做（与子代理记录「已发生部分可回看」语义一致）。
8. 作为用户，我想子代理没建计划时详情不渲染计划卡也不占布局行，以便界面保持干净。
9. 作为用户，我想多个并行子代理各自有独立计划卡互不干扰，以便同时跟踪多个委派的进度。
10. 作为用户，我想子代理计划与主任务计划完全独立（互不覆盖、互不混杂），以便两个计划各答各的问题——主任务管全局编排，子代理管自己的内部步骤。
11. 作为用户，我想子代理工具调用清单里 update_plan 行显示中文统计摘要（共 N 项：X 已完成、Y 进行中、Z 待办），以便回看历史计划更新时不读压缩 JSON。
12. 作为用户，我想导出子代理记录时在最终报告之前带「## 工作计划」终态段，以便离线归档与分享同样能看到计划全貌与完成度。
13. 作为用户，我想重启应用后子代理计划卡照常显示（含已完成与已中断的子代理），以便回看不依赖运行期内存。
14. 作为用户，我想子代理建计划/更新计划的行为受使用策略引导（多步任务开工先建完整计划、计划未完成不提前收尾、正文不解说规则本身），以便子代理稳定产出可跟踪的进度，报告读起来自然连贯。
15. 作为用户，我想子代理的 update_plan 调用免审批（readonly 工具），以便维护计划不产生审批打断。
16. 作为用户，我想子代理的最终报告保持纯文本结论（不附带机器统计行），以便主代理与我读到的报告自然连贯。
17. 作为本仓库的开发者，我想子代理工具表与提示注入的既有断言随本特性反转为正向（工具表含 update_plan、提示含工作计划策略与风格条款），以便测试口径与 ADR 0023 一致。
18. 作为本仓库的开发者，我想 dev fixtures 带子代理 update_plan 样例，以便 dev 预览里直接看到计划卡形态。

## Implementation Decisions

- **工具挂载**：子代理编排器把 update_plan 工具强制并入每次子代理运行的工具表，同 questionsTool 模式；资源快照 execution tools 与其撞名即拒绝。工具本体复用主任务同一实现：readonly 免审批、全量替换语义、计划项 1–50 项/内容 ≤200 字符、执行输出为中文统计摘要。
- **策略注入**：工作计划使用策略（PLAN_USAGE_POLICY）与通用风格条款（TOOL_STYLE_POLICY）复用同一常量静态注入子代理系统提示（随子代理角色指令一次性组装，子代理无每轮注入机制）；「计划未全部完成前不结束回合」持续执行条款随之适用子代理。
- **归属模型**：主任务与每个子代理各自独立维护计划，互不汇聚、互不可见；主任务计划里「等子代理完成」只是普通计划项。
- **数据通道（派生式，零新存储/零新事件）**：子代理计划状态即子代理工具调用记录（subagent_tool_calls 表中 toolName 为 update_plan 的行，随 ADR 0021 既有通道持久化与恢复）；UI 以纯函数从子代理工具调用序列派生快照，「当前计划」= 最后一次 update_plan 的参数，解析复用既有 parsePlanSteps。
- **详情挂卡**：子代理详情滚动容器末尾复用主任务进度折叠卡组件（WorkPlanCard，按 items + 作用域 id 参数化），开合记忆走 collapse-memory、作用域按 subagentId；无计划渲染 null 不占布局行；运行中/已完成/已中断均常驻。
- **工具清单摘要行**：工具摘要纯函数（summarizeToolCall）加 update_plan 专项分支，输出与工具执行输出同口径的中文统计摘要；工具调用计数照常含 update_plan。
- **导出终态段**：子代理导出 Markdown 在「## 最终报告」之前插「## 工作计划」终态段（完整清单三态），无计划省略该段。
- **零改动的面**：主任务消息流、主任务计划卡、子代理列表摘要行/当前选中行、子代理报告契约、主任务模型上下文组装均不变；子代理计划不产生主消息流段。

## Testing Decisions

- 只测外部行为（工具表内容、提示内容、落库记录、派生快照、渲染/导出结果），不测内部调用次序与私有结构。全部走既有 seam，零新 seam：
  - **S1 agent-core 行为 seam**：子代理装配器 harness（makeSubagentTask）——工具表含 update_plan、子代理提示含工作计划策略与风格条款、update_plan 在子代理循环执行并逐条落 subagent_tool_calls 表；既有两条反向断言（工具表不含、提示不含）反转为正向。先例：subagents.test.ts（ADR 0021 落库断言、策略注入断言）。
  - **S2 ui 纯函数 seam**：plan-view 子代理收集薄壳、工具摘要统计分支、导出终态段。先例：work-plan-ui、tool-view、subagent-export 测试。
  - **S3 ui 渲染 seam**：子代理详情结构断言——有计划渲染卡、无计划不渲染、三态回看、开合记忆按 subagentId。先例：subagent-rail-ui、subagent-view 测试。
  - **S4 e2e 全链**：子代理建计划 → 更新 → 完成 → 重启回看计划卡。先例：subagent-interrupted、work-plan e2e 场景。
- agent-core 源码改动后须重建 dist 再跑 desktop/ui 测试（两包 test script 已前置 build，照常直跑即可）。

## Out of Scope

- 汇聚式：主任务计划自动聚合各子代理进度。
- 子代理报告附带计划完成度摘要（未完成信号已有撞限截断标记与中断联动兜底）。
- 子代理列表摘要行/当前选中行的计划进度微显示。
- 子代理详情内主消息流式的计划标记行（PlanMarkerRow）机制。
- 主任务侧任何呈现与契约改动。
- 新存储表、新事件类型、新 IPC 通道。
- 嵌套子代理（本就不存在，防递归边界不动）。
