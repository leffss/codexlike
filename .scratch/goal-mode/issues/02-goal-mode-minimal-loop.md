# 02: 目标模式最小闭环（tracer bullet）

**What to build:** 用户输入 `/goal <目标文本>`，任务进入目标模式并端到端走通一次：目标原文作为用户消息显示在消息流；设定即触发首轮正常回合；回合结束后 goal 编排器（desktop，idle 边界，落位先例=输入队列）发起**完成判定**（agent-core：任务当前模型、无工具、目标文本+完整消息历史）；本票场景判定**通过** → 目标转「已完成」。输入框上方出现目标进度行（目标摘要、状态、累计时长）。Stop 按钮在目标进行中 = 暂停。目标进行中输入队列不自动消费、终态后恢复。目标实体（六态状态机）与逐轮验证记录随任务落库。

**Blocked by:** 01

**Status:** ready-for-agent

**上下文指针:** `.scratch/goal-mode/spec.md`（Implementation Decisions 全节）、`.scratch/goal-mode/notes.md`（agent-core/desktop/ui 各节 + e2e 纪律）、ADR 0035、GLOSSARY「目标 / 目标模式 / 完成判定」

- [ ] `/goal <目标>` 设定成功走本地命令反馈；原文以用户消息呈现；无效输入（空目标等）反馈失败原因不落库
- [ ] 设定后目标「进行中」、任务侧 status 四值不变、占任务并发一席口径照旧；进度行显示摘要/状态/累计时长
- [ ] 首轮回合结束自动发起判定；判定通过 → 「已完成」，消息流出现「第 1 次迭代 · 已完成」标记行
- [ ] Stop 在目标进行中 = 暂停（转「已暂停」；恢复按钮在票 04，本票内暂停后不得自行无限续跑、目标不丢失）
- [ ] 目标进行中输入队列不自动消费；终态后恢复逐条自动发出（「等待用户交互期间输入框不可用」等既有规则不变）
- [ ] 目标实体与验证记录随任务落库，重启后可读（恢复为暂停态的完整语义在票 06）
- [ ] agent-core 单测绿：六态状态机转换、判定请求构造与响应解析容错、fail-open 基础行为
- [ ] desktop 单测绿：编排器单次流转（回合结束→判定→完成）、队列互锁守卫、`/goal` 命令解析
- [ ] ui 单测绿：进度行最小呈现（状态/摘要/时长/空态）
- [ ] e2e 场景「设定→一轮→判定通过→已完成」实跑绿（含队列恢复断言；agent-core 改动后重建 dist 再跑）
