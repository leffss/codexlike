# Spec: 输入队列（Input Queue）

Status: done

术语依 `GLOSSARY.md`：**输入队列**、**排队消息**、**队列暂停**、**会话**、**用户交互**。架构决策见 ADR 0013。

## Problem Statement

用户在 agent 回复进行中想到后续指令时，只能干等回复结束再手动发送：输入框可以打字，但 Enter 与发送按钮均被禁用（「运行中仍可准备下一条」只是草稿）。多步任务里这意味着用户必须守在屏幕前，逐条等待、逐条发送；想先打断再说话，又得丢掉「按顺序自动继续」的可能。

## Solution

会话忙时，用户提交的普通消息进入该会话的**输入队列**：输入框上方显示紧凑队列条，消息可编辑（原地更新）、可删除、可拖拽重排；会话空闲后由主进程自动逐条发出，与用户正在查看哪个会话无关。停止打断后队列保留并暂停，插话完成后自动恢复；队列随会话持久化，重启后自动继续。详见下方用户故事与实现决策。

## User Stories

1. 作为用户，我想在 agent 回复进行中把新消息加入输入队列，以便不用干等就能把后续想法说出来。
2. 作为用户，我想让排队消息在当前回复结束后自动逐条发出（发一条、等其回复完成、再发下一条），以便不用守着屏幕逐条手动发。
3. 作为用户，我想在输入框上方看到紧凑队列条，以便一眼知道有几条消息在排队。
4. 作为用户，我想队列超过 5 条时折叠显示「+N 更多」，以便队列很长时界面不喧宾夺主。
5. 作为用户，我想在回复进行中且输入框有内容时看到「加入队列」与「停止」按钮并排，以便既能排队又不失去随时打断的能力。
6. 作为用户，我想在回复进行中且输入框为空时只看到停止按钮，以便界面保持与现状一致。
7. 作为用户，我想点停止后队列原样保留并进入队列暂停，以便打断当前回复而不丢失已排队的消息。
8. 作为用户，我想在队列暂停状态下手动恢复消费，以便自己决定什么时候继续。
9. 作为用户，我想在队列暂停状态下清空整个队列，以便作废所有排队消息。
10. 作为用户，我想在队列暂停期间直接发新消息（会话空闲，无需先解除暂停），以便插话没有额外步骤。
11. 作为用户，我想插话的回复结束后队列自动恢复消费，以便暂停只是插话窗口而不是永久冻结。
12. 作为用户，我想点击排队消息把内容取回输入框编辑，以便修正错字或补充细节。
13. 作为用户，我想取回编辑后重新提交时消息保持在队列原位，以便编辑不意外改变发送顺序。
14. 作为用户，我想拖拽重排队列中的消息，以便按新的优先级发送。
15. 作为用户，我想删除单条排队消息，以便撤掉某条不再想要的消息。
16. 作为用户，我想在回复进行中提交斜杠命令时得到提示而不入队，以便命令不会在错误的时机被延迟执行。
17. 作为用户，我想在 agent 等待用户交互（审批/问答）期间输入框保持禁用，以便不会有排队消息卡在无法消费的时机。
18. 作为用户，我想每个会话拥有独立、互不影响的输入队列，以便在 A 会话排队的消息永远不会发到 B 会话。
19. 作为用户，我想切换会话时各会话的队列原样保留，以便切回来还能看到并继续处理。
20. 作为用户，我想重启应用后队列原样恢复并自动继续消费，以便重启不丢失已表达的发送意图。
21. 作为用户，我想排队时把当时的 Provider Profile、思考档位、审批模式一并快照，以便消费时按我排队时的意图发送。
22. 作为用户，我想队列没有条数上限，以便长任务清单也能一次排完。
23. 作为用户，我想后台会话的队列在我没有打开该会话时也自动消费，以便离开时工作也在推进。
24. 作为用户，我想 @文件引用随排队消息一起保存，以便消费时引用内容完整生效。
25. 作为用户，我想看到队列中「正在发出」的那条与仍在排队的条目区分开，以便知道消费进行到哪了。

## Implementation Decisions

- **架构（ADR 0013）**：队列状态与消费循环位于 desktop 主进程的会话层，随会话持久化到 SQLite（与会话消息同库）；agent-core 的 busy 互斥保持不变、不感知队列；渲染层只呈现与操作。
- **队列模块（新，主进程）**：每会话一个队列实例，接口语义覆盖：入队（消息 + 参数快照）、取队首发送、消费循环（会话空闲即取下一条，等其回复完成再继续）、暂停、恢复、清空、原地编辑、删除、重排。
- **入队路径单一真相在主进程**：现有 send IPC 在会话忙时不再报错，而是将消息入队（含参数快照）；渲染层「忙时 Enter」直接调用 send，无需自行判断。斜杠命令的拦截仍在渲染层（命令不入队）。
- **消费触发**：会话执行结束（activity running=false）后尝试取队首；入队时若会话已空闲则立即触发消费；应用启动时扫描所有会话，队列非空且会话空闲的自动开始消费（重启自动继续）。
- **暂停语义（精确）**：暂停是队列级标志。手动恢复与「插话完成」都会清除该标志：队列暂停期间直接发送的新消息（插话）完成后，自动清除暂停标志并继续消费队列。
- **消费中条目**：已被取出发送的消息视为出队，不可编辑、删除或重排；队列操作只作用于仍在排队的条目。
- **IPC 契约**：新增队列操作通道（编辑、删除、重排、暂停、恢复、清空）与队列状态查询；队列变更作为会话事件流的一部分推送（入队、出队发送、条目变更、暂停/恢复），复用现有事件信封与会话/序号过滤，渲染层据此渲染队列条。
- **持久化形状**：排队消息按会话存储，至少含：顺序位置、消息文本、@引用、Provider Profile、思考档位、审批模式、入队时间；消费成功后从队列移除并入会话消息历史。
- **UI**：输入框上缘的紧凑队列条（不进消息流，显示条目预览，>5 折叠「+N 更多」，暂停态显示恢复/清空操作）；忙且有输入时「加入队列」+「停止」并排双按钮，无输入时仅停止；队列条目支持点击取回编辑（原地更新）、删除、拖拽重排。
- **等待用户交互期间**：输入框维持现有禁用行为，不提供入队。

## Testing Decisions

- 只测外部行为（队列的可见状态转移与消费结果），不测实现细节。
- **队列模块单测**（唯一新接缝，位于 desktop 会话测试目录，形态参照现有注册表类纯逻辑测试先例）：逐条消费时序、忙时入队不丢、暂停门控与插话后自动恢复、原地编辑不变序、重排、删除、参数快照随消息保存、持久化往返（存取后状态一致）。
- **IPC/会话层集成测试**：按现有会话 IPC 测试模式补充——忙时 send 变入队、队列事件推送、操作通道生效。
- **e2e**：新增一个 e2e 用例文件（参照现有中断用例的驱动方式）：回复进行中入队 → 队列条显示 → 回复结束自动逐条消费；停止 → 暂停 → 插话 → 自动恢复；重启后队列自动继续；忙时双按钮并排。
- UI 组件不强制单独单测，由 e2e 覆盖；实现中若出现非平凡 view-model 逻辑，按现有 UI 测试模式补测。

## Out of Scope

- 斜杠命令的排队或延迟执行。
- 等待用户交互（审批/问答）期间的输入排队。
- 排队消息跨会话移动或复制。
- 队列条数上限与满员策略。
- 队列条目的键盘重排（无障碍操作细节，后续迭代）。
- 排队消息内容的流式预览。

## Further Notes

- 术语已录入 `GLOSSARY.md`（输入队列 / 排队消息 / 队列暂停）；架构决策见 `docs/adr/0013-input-queue-consumed-in-main-process.md`。
- 会话切换不打断执行的既有行为（GLOSSARY「会话」）天然支撑后台会话队列消费，无需新增机制。
- 思考档位的既有语义（「调整只影响下一次发送」）与参数快照一致：排队消息按入队时快照发送。
