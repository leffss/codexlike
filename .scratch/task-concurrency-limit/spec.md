# 任务并发上限与任务排队（Task Concurrency Limit & Task Queue）

## Problem Statement

任务可以无限同时运行：开几个任务就有几份模型调用与本机资源占用同时发生，用户没有任何手段控制「同时跑多少个任务」。想要一个可配置的上限，放在设置里。

## Solution

新增全局任务并发上限（1-8，默认 3），放进设置页「执行」分区。达到上限时，新任务的首条执行不再立即开跑，而是进入应用级 FIFO 任务排队，有空位自动按发起顺序开跑。排队状态在侧栏（「排队中」徽章）与任务内（状态条）可见，可中断出队，跨重启保留并自动恢复。运行中任务不受调小上限影响；调大上限立即补跑排队任务。词汇与决策见 GLOSSARY「任务并发上限」「任务排队」「排队任务」词条与 ADR 0022。

## User Stories

1. As a 用户, I want 设置同时执行的任务个数上限（1-8，默认 3）, so that 我能控制模型调用花费与本机资源占用。
2. As a 用户, I want 达到上限时新任务自动排队而不是被拒绝, so that 我不用手工重试首条消息。
3. As a 用户, I want 排队任务在有空位时自动按发起顺序（FIFO）开跑, so that 无需盯守、顺序可预期。
4. As a 用户, I want 侧栏任务列表显示「排队中」徽章, so that 一眼区分排队、运行中、等待用户的任务。
5. As a 用户, I want 打开排队任务时看到已发出的首条消息和「排队中」状态提示（含当前运行数）, so that 明白它为什么还没开始回复、大概还要等多久。
6. As a 用户, I want 排队期间继续在排队任务里输入消息（进入该任务输入队列）, so that 不必等开跑才补充要求。
7. As a 用户, I want 中断排队中的任务, so that 反悔时立刻出队、不占后续名额。
8. As a 用户, I want 中断排队后任务回到空闲、已发消息保留在消息流, so that 之后可以重新发消息触发执行。
9. As a 用户, I want 重启应用后排队任务按原顺序自动继续开跑, so that 重启不丢排队语义（与输入队列跨重启行为一致）。
10. As a 用户, I want 把上限调大时排队任务立即补位开跑, so that 调参立刻见效。
11. As a 用户, I want 把上限调小时运行中任务不被中断, so that 调参不打断进行中的工作，新任务继续排队直到自然降下去。
12. As a 用户, I want 在设置页「执行」分区找到这个设置项（与工具轮次上限等并列）, so that 不用到别处找、分区语义一致。
13. As a 用户, I want 非法输入（越界、非整数）被校验拦下或回退默认, so that 配置不会进入坏状态。
14. As a 用户, I want 等待审批/问答的任务仍占用名额, so that 「并发数」语义诚实——不会出现恢复执行时被新任务挤压排队的反直觉行为。
15. As a 用户, I want 子代理并发行为完全不变, so that 既有子代理工作流不受影响。
16. As a 用户, I want 排队任务照常创建（侧栏可见、可点开）, so that 排队不等于任务不存在。
17. As a 升级用户, I want 升级后默认上限 3 即刻生效, so that 新机制开箱即用（第 4 个任务排队属预期行为变化，ADR 0022）。
18. As a 用户, I want 排队机制与任务内输入队列互不干扰, so that 既有消息排队行为（暂停、插话、跨重启）原样保留。

## Implementation Decisions

- **设置落点**：任务并发上限并入执行设置（agent-settings store + IPC + 主进程内存缓存 + 设置页分区，四件套全复用扩展一个字段）。消费点在 desktop 主进程发送闸门，**不经 agent-core**——agent-core 无全局任务并发概念，也不为其新增（与执行设置其余六项的 resolver→agent-core 注入路径不同，ADR 0022）。
- **任务排队协调器**：desktop 主进程 `src/tasks/` 下新独立模块，依赖全注入（上限 resolver、执行中判定、开跑回调、持久化、变更通知），形态紧贴输入队列协调器（唯一新测试 seam）。
- **闸门与推进**：任务发送路径上，首条执行因满员改入队；名额释放点 = 执行结束（正常完成、失败、被中断，含等待用户交互后继续至结束），释放时按 FIFO 推进队列。
- **占坑口径**：名额从执行开始占到执行结束；执行中途等待审批/问答（waiting-user）期间不释放（ADR 0022）。
- **排队期间的输入**：排队任务在输入队列语义上视同「忙」——后续消息进该任务输入队列，开跑后按序自动发出；完全复用 ADR 0013 机制，不改其行为。
- **持久化**：排队状态随任务持久化（任务记录新增排队态或独立有序队列表，由实现按存储现状选择，语义等价：能按序恢复）；重启后应用启动时按序自动开跑（上限内）。
- **设置生效语义**：改动即时生效于队列——调大立即补跑、调小只拦新；不做「回合开始快照」（补跑的是尚未开始的任务，与 ADR 0017 不冲突）。
- **中断排队**：出队回空闲，已发消息保留；之后用户再发消息重新触发执行（若仍满则重新排队）。
- **呈现**：任务活动状态新增 `queued` 态并随任务列表下发，侧栏徽章新增「排队中」样式；任务内顶部状态条显示排队提示；执行设置分区新增并发上限输入项。
- **校验**：1-8 整数、默认 3，越界回退/拒绝沿执行设置现有防护语义。
- **明确不做**：手动插队/调序、「不限」档、按项目分设上限、取消排队自动重发、子代理并发变更、输入队列行为变更。

## Testing Decisions

- 只测外部可见的状态转移与用户可见行为，不测内部实现细节（沿输入队列测试的既有精神）。
- **协调器单测**（新 seam，仿输入队列单测的依赖注入模式）：FIFO 入队/出队、占坑含 waiting-user、调大补跑/调小拦新、中断出队、重启后按序恢复——全部用注入假件。
- **IPC 集成**（沿任务 IPC 测试先例）：满员时 start 入队不执行、名额释放自动开跑、任务列表附带 queued 活动态、中断排队出队。
- **设置链路**（沿执行设置 store/IPC 测试先例扩展）：范围校验、默认值、越界回退。
- **UI 组件**（沿侧栏与执行设置测试先例）：「排队中」徽章渲染、执行分区新输入项、任务内排队状态条。
- e2e 场景（并发满员→排队→空位开跑）由票据阶段按 e2e 既有模式决定拆法。

## Out of Scope

- 手动插队/调整排队顺序、排队优先级
- 「不限」档（想要宽松就设 8）
- 按项目分别设置上限
- 取消排队后的自动重发机制
- 子代理并发的任何变更（维持 1-8 默认 3 现状）
- 任务内输入队列的行为变更（只复用不改：暂停、插话、跨重启语义原样）
