# 02: 任务排队协调器与发送闸门——满员 FIFO 入队、空位自动开跑

**What to build:** 把票 01 的上限变成真实闸门：同时执行的任务数达到上限时，新任务的首条执行进入应用级 FIFO 任务排队而非立即开跑；名额从执行开始占到执行结束（等待审批/问答期间不释放，ADR 0022），释放时按发起顺序自动开跑；调大上限立即补跑排队任务、调小不中断运行中的；任务活动状态新增 `queued` 并随任务列表下发。排队协调器是独立模块、依赖全注入（上限 resolver、执行中判定、开跑回调、持久化接口、变更通知），本票内存态即可，持久化实现留给票 05。

**Blocked by:** 01（消费设置值）

**Status:** done

- [ ] 上限 2 时第 3 个任务的首条执行入队不执行；结束一个后自动开跑，顺序严格 FIFO
- [ ] 等待审批/问答的任务占名额：3 个在等用户时第 4 个任务排队
- [ ] 调大（2→4）排队任务立即补位开跑；调小（4→2）运行中不被中断、新任务继续排队直到自然降下
- [ ] 任务列表 IPC 下发 `queued` 活动态（侧栏徽章渲染是票 03）
- [ ] 协调器单测（依赖注入假件，仿输入队列测试模式）覆盖 FIFO 入队/出队、占坑含 waiting-user、调大补跑/调小拦新的状态转移
- [ ] IPC 集成测试（仿 tasks IPC 测试先例）覆盖满员入队与空位自动开跑
