# 02: 主会话思考档位与折叠展示全链路

**What to build:** 用户在审批胶囊旁选择思考档位，下一条发送通过 IPC 将选择传到模型，并在主会话中流式查看独立、可折叠的思考内容。打通完整用户路径，不只交付 core 事件或 UI 占位。

**Blocked by:** [01: 迁移兼容 provider，守住现有行为](01-compatible-provider.md)。01 提供已经验证的模型工厂、请求参数和 reasoning 流契约。

**Status:** ready-for-agent

## Parent

[思考档位 spec](../spec.md) 是完整契约；实施前阅读生效边界、接入契约和事件展示要求。

## Acceptance criteria

- [ ] 输入框工具栏审批胶囊旁提供胶囊内嵌 select：自动、低、中、高、关；默认自动，显示文字及档位颜色，具备可访问名称和键盘可操作性，无会话时禁用。
- [ ] 档位为前端临时发送设置，不建立会话级持久化或全局设置；不新增 schema，不保存最近使用档位，不改变既有模型选择记忆方式。
- [ ] 运行中仍可修改选择；发送入口固定本条消息快照。一次发送内所有工具往返保持该档位，下一条消息才采用新选择，历史消息不修改、不重算。
- [ ] 五档通过 IPC 与 Agent Core 公共发送入口传到最终请求 body，符合 spec 的映射；未传字段的调用按 `auto` 处理，枚举边界得到验证。
- [ ] 主会话独立关联 reasoning 与正文，流式思考块可展开/收起；不把思考拼进 assistant 正文，连续工具轮次及不同消息不串流。
- [ ] 只有思考尚无正文、没有 reasoning、正常结束、失败和停止均有正确展示；取消后不残留思考进行中状态，也不继续追加内容。
- [ ] 思考内容不进入持久化消息、历史恢复或后续请求上下文；不主动开启 `clear_thinking: false`。重启后不声称能恢复思考内容。
- [ ] compact 和 commit 草稿不使用胶囊选择，不附加控制参数；本票保持子代理既有行为，子代理继承及展示由 03 交付。
- [ ] 服务端拒绝不支持的档位时沿用错误展示，不静默降档，不增加兼容性自动重试；UI 不声称“关”能强制所有模型关闭思考。
- [ ] 主会话公开入口测试覆盖档位快照、跨消息切换、事件隔离、终态处理以及不持久化/不回传；复用现有 UI 状态归并测试。
- [ ] Desktop E2E 从选择胶囊到本地 mock provider 的实际请求 JSON贯通验证，并检查流式思考与正文隔离、折叠交互、运行中切档只影响下一条消息。
- [ ] 执行相关单测和新增端到端场景，记录真实退出码及结果；保留已有对话、工具与取消行为。

## Testing notes

沿用既有模型 mock、事件收集器、内存持久化及 desktop 本地 HTTP/SSE mock。UI 状态断言验证归并语义；折叠可操作性和完整 IPC 链路由 E2E 验证。以可观测行为为断言，不锁死内部函数调用和 CSS 实现。
