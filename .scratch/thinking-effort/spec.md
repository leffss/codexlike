# 思考档位：主会话与子代理的逐消息控制和流式展示

**Status:** ready-for-agent

## Problem Statement

用户希望根据任务难度随时调整模型思考强度，并在等待回复时看到思考过程。当前会话不能控制思考档位，也不能展示兼容端点返回的思考内容；子代理同样缺少这些能力。模型接入来自用户配置的 Provider Profile，各服务端的支持范围不同，客户端不能把参数已发送等同于模型已支持。

## Solution

在输入框工具栏的审批胶囊旁增加思考档位胶囊，提供自动、低、中、高、关，默认自动。用户可以在会话运行期间修改选择，但只有下一条发送的消息采用新值；本条消息的工具循环和它触发的子代理保持发送时的快照。

主会话回复和 SubagentCard 分别流式展示独立、可折叠的思考内容。档位选择和思考展示均为临时状态，不增加会话持久化字段，也不提供历史思考恢复。子代理继承触发消息的档位，但继续使用既有的子代理模型选择规则。

## User Stories

1. 作为用户，我希望默认使用自动档位，以便保留服务端默认行为。
2. 作为用户，我希望选择低、中、高档位，以便按任务需求调整思考强度。
3. 作为用户，我希望选择关，以便向允许关闭思考的模型明确发出关闭请求。
4. 作为用户，我希望在审批胶囊旁直接切档，以便无需离开会话进入设置页。
5. 作为用户，我希望控件显示当前选择且支持键盘操作，以便不只依靠颜色辨别档位。
6. 作为用户，我希望模型运行期间仍能选择下一条消息的档位，以便提前准备下一轮请求。
7. 作为用户，我希望一次发送中的所有工具往返保持相同档位，以便中途修改不会改变正在执行的任务。
8. 作为用户，我希望切档不会修改或重算历史消息，以便既有对话保持原样。
9. 作为用户，我希望主会话思考内容与正文分开展示，以便区分推理过程和最终答复。
10. 作为用户，我希望思考内容随流更新且可展开或收起，以便观察进度而不占满消息区域。
11. 作为用户，我希望未返回思考内容的回复仍正常展示，以便兼容普通模型与自动档位。
12. 作为用户，我希望停止任务时思考流也停止，以便不会出现一直显示思考中的残留状态。
13. 作为用户，我希望服务端拒绝某个档位时能看到错误，以便知道请求没有按预期完成。
14. 作为用户，我希望子代理自动继承触发消息的档位，以便主任务与委派任务使用相同思考设置。
15. 作为用户，我希望子代理使用独立 Provider Profile 时仍继承档位，以便模型选择和思考设置各司其职。
16. 作为用户，我希望排队的子代理也保留触发时的档位，以便等待期间的切档不会改变任务配置。
17. 作为用户，我希望每张 SubagentCard 能独立折叠和展示对应的思考内容，以便并发任务之间不混淆。
18. 作为用户，我希望子代理完成、失败或中断时其思考显示也正确结束，以便准确理解任务状态。
19. 作为用户，我希望重启后不被告知存在可恢复的思考历史，以便界面与本次仅临时展示的边界一致。
20. 作为用户，我希望 compact 和 commit 草稿维持服务端默认行为，以便本次会话选择不会意外改变辅助调用。
21. 作为用户，我希望迁移 provider 后原有文本、工具调用、审批和取消能力保持可用，以便新能力不破坏既有任务。

## Implementation Decisions

### 领域与生效边界

- 使用领域词「思考档位（Thinking Effort）」，取值为 `auto / low / medium / high / off`；初始值为 `auto`。
- 档位选择与现有模型选择一样属于前端临时发送设置，不建立新的会话级记忆，也不落库记录最近使用档位。
- 每次发送在入口形成快照，并作为明确参数贯穿 IPC 与 Agent Core。同一用户消息触发的所有模型请求、工具往返均使用此快照；不是每次底层 HTTP 调用重新读取 UI 当前值。
- 子代理继承触发它的主会话消息快照，包含延迟或排队启动的任务；运行期间不随 UI 改动。子代理模型仍按既有独立 Profile 配置及回退规则选择。
- 缺省档位按 `auto` 处理，保证未传该字段的既有调用方可继续工作；边界接受值限于上述枚举。

### 接入契约

- 遵循 ADR 0006，在统一模型工厂迁移至 `@ai-sdk/openai-compatible`，继续使用 chat completions 兼容协议，不引入 Responses API。
- 最终 HTTP 请求 body 的契约如下；SDK 内部选项名和命名空间由实际安装版本与请求测试确定，不把内部 camelCase 名称当作网络协议。

| 档位     | 本功能附加的请求字段                                   |
| -------- | ------------------------------------------------------ |
| `auto`   | 不附加 `thinking` 或 `reasoning_effort`                |
| `low`    | `thinking.type = enabled`，`reasoning_effort = low`    |
| `medium` | `thinking.type = enabled`，`reasoning_effort = medium` |
| `high`   | `thinking.type = enabled`，`reasoning_effort = high`   |
| `off`    | `thinking.type = disabled`，不附加 `reasoning_effort`  |

- compact 与 commit 草稿不附加档位控制参数；它们仍共享迁移后的模型工厂，因此必须参与回归。
- 本次不建设模型能力目录。所有 Profile 使用同一五档控件；服务端可能拒绝或忽略不支持的参数，沿用现有错误呈现，不静默降档，也不新增针对档位不兼容的自动重试。
- 自动表示由服务端决定，并不代表关闭；关表示已发送关闭请求，并不保证强制思考模型实际停止思考。
- 迁移验证必须包括 baseURL、鉴权、模型标识、文本流、工具调用及工具结果往返、错误与取消。依赖版本以落地时锁文件和兼容性验证为准，不沿用调研期间的版本号作为安装指令。

### 事件与展示

- Agent Core 将 provider 的 reasoning 流转为独立的主会话和子代理事件。事件带有足够的消息或子代理关联信息，避免并发和连续工具轮次串流。
- 思考与正文分别累积；主会话和每张 SubagentCard 都提供流式、可折叠的思考区域，不将思考拼进最终正文或子代理报告。
- 思考进行中、正常结束、错误和中断都应收敛到正确的展示状态；只有思考尚无正文的场景也能被取消和结束。
- 无 reasoning 返回时正常显示现有文本、工具和子代理行为，不伪造思考过程。
- 控件使用胶囊内嵌 select，位于审批胶囊旁，以档位颜色和文字区分；无会话时禁用，运行中允许为下一条消息改档。复用现有受控组件与可访问性模式。
- 思考内容只用于当前运行期展示，不写入消息数据库，不在恢复历史时重建，不主动启用 `clear_thinking: false` 或构造思考历史回传。需检查新 provider 的消息转换，避免误把展示内容自动加回上下文；若服务端协议要求必传思考内容，则报告兼容性限制，不悄悄扩大本次范围。

## Testing Decisions

- 只测公开行为和网络契约，优先使用已有高层入口；不通过断言内部函数调用顺序或具体 CSS 类锁死实现。
- **模型工厂 → HTTP：**复用 provider 测试的 fetch spy，断言实际序列化 JSON；表驱动覆盖五档，验证 `auto` 与辅助调用省略参数。使用受控响应验证普通文本和 reasoning SSE 转换，覆盖工具调用回归。
- **主会话/子代理入口 → 事件：**复用模型 mock、事件收集器和内存持久化设施，验证思考正文隔离、完成/取消/失败、消息间切档、单次发送内档位不变、排队及并发子代理快照。验证思考内容未进入持久化消息与后续请求历史。
- **UI 状态归并：**复用现有 session-view 状态测试，验证 reasoning 事件只更新所属消息/子代理，结束状态不残留，历史加载不制造不存在的思考块。
- **Desktop E2E → 本地 mock provider：**复用真实本地 HTTP/SSE 服务及请求 body 收集器，从胶囊选择贯通 IPC 和模型调用，验证主会话与 SubagentCard 的流式展示、展开/收起、切档以及独立 Profile 子代理继承。
- 迁移票和最终子代理票执行全量单测及项目全套 E2E；主会话票执行相关单测与新增端到端场景，并保持基线可用。具体命令读取当前 package scripts，检查命令直接取退出码，不接截断输出的管道。
- mock 成功只证明客户端契约，不宣称真实远端支持全部档位。记录失败和环境阻塞，不能将未运行或跳过的测试写成通过，也不沿用旧测试数量。

## Out of Scope

- 全局默认设置、每会话档位记忆、最近使用档位审计字段及任何数据库 schema 迁移。
- 思考内容持久化、重启恢复思考历史、主动启用 Preserved Thinking 或思考历史回传。
- `/thinking` 命令、第二个独立开关、`max` 等额外档位、模型能力探测或档位自动映射。
- 子代理独立档位配置、对子代理实时广播档位修改。
- 改变 compact/commit 草稿的档位策略，或扩展现有模型选择的持久化语义。
- 不兼容档位的自动降级、重试策略，以及真实服务端支持范围的承诺。
