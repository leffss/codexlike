# 消息流重构规格

**Status:** ready-for-agent

用户已确认全部产品决策(grilling 会话逐项确认)、测试接缝方案与验收口径。本规格是实施与验收依据;[ADR 0011](../../docs/adr/0011-message-stream-timeline-model-and-reasoning-persistence.md) 记录关键取舍,[ZCode 调研报告](../../docs/research/zcode-message-stream.md) 记录设计参考(借鉴思想,不复制代码),术语见 [GLOSSARY.md](../../GLOSSARY.md) 的消息流、消息段、轮次、跟随、已工作折叠区条目。发布规格不代表业务实现已经开始。

## Problem Statement

消息流(会话主界面滚动区)当前有三个用户可感知的缺陷:流式输出时页面不会自动跟随到最新内容,用户要不断手动下翻;思考过程、正文与工具调用的显示顺序混乱——思考被提升到气泡顶部、工具调用之后产生的正文显示在工具卡上方,与真实发生顺序脱节;消息宽度被锁死在 768px,宽屏下代码块、diff 和表格空间不足。

根因在数据层:会话视图把事件按类型归类合并(思考拼进气泡顶部单一字段、工具卡追加到列表末尾而后续正文又合并回靠前气泡),事件间的时序交错在归并时已丢失,渲染层无法恢复。此外思考过程只存在于渲染进程内存,重启或切回会话后消失;历史恢复路径完全丢弃思考字段。

## Solution

把会话视图数据模型改为按事件发生时序排列的扁平消息段序列:思考段、正文段、工具调用卡、子代理卡、错误段、状态段与 compact 摘要段都是序列中的平等成员,带稳定序号与轮次标签,渲染层如实按时序呈现,并以轮次为单位分组(细分隔线+轮间距)。

滚动引入显式跟随状态机:贴近底部时自动追踪最新内容,用户向上翻阅立即脱离跟随且不被流式输出拉回,提供"回到最新"入口,发送新消息强制回到底部。

每轮完成后,最终正文之前的全部过程(思考、工具调用、中间正文)默认收进"已工作 N 秒"折叠区,历史会话收起后只剩最终正文;运行中的轮与中断、失败的轮强制展开过程。思考过程随终态消息落库,重启与切回会话后可回看。消息宽度改为按会话容器分档(最宽 1152px),消息流、头部与输入区对齐共用。

## User Stories

**滚动跟随**

1. 作为用户,我希望消息流贴近底部时自动跟随最新内容,以便流式输出期间不必手动下翻。
2. 作为用户,我希望向上翻阅历史时立即脱离跟随,以便阅读不被新内容不断拽到底部。
3. 作为用户,我希望脱离跟随后流式增量、工具卡更新都不改变我的阅读位置,以便安心读历史。
4. 作为用户,我希望脱离跟随时出现"回到最新"入口,点击后回到底部并恢复跟随。
5. 作为用户,我希望手动滚回底部附近后自动恢复跟随,以便继续追踪新内容。
6. 作为用户,我希望发送新消息后强制回到底部并进入跟随,以便立刻看到 agent 开始工作。
7. 作为用户,我希望程序化贴底与内容变高产生的滚动不改变跟随状态,以便只有我的滚轮、触摸和按键意图说了算。
8. 作为用户,我希望上翻的瞬间恰好碰上流式内容更新时,我的上翻仍然生效,以便竞争不吞掉滚动意图。
9. 作为用户,我希望贴底跟随是即时定位而非平滑滚动,以便流式期间不抖动。

**阅读位置记忆**

10. 作为用户,我希望切换会话再切回时恢复上次的阅读位置,以便继续读到一半的历史。
11. 作为用户,我希望离开时若正贴底,切回时直接定位到当前最新并继续跟随,以便不落回过时的像素位置。
12. 作为用户,我希望新会话打开时直接定位到最新消息,以便没有多余操作。

**时序保真**

13. 作为用户,我希望思考、正文、工具调用按真实发生顺序显示,以便回看时理解 agent 的工作过程。
14. 作为用户,我希望工具调用之后产生的正文显示在该工具卡之后,以便叙述与操作对应。
15. 作为用户,我希望多段思考之间穿插的工具调用保持交错顺序,以便不被归并成顶部一大块。
16. 作为用户,我希望每轮回复以轮次分组呈现(细分隔线+轮间距),以便长会话仍有清晰结构。

**已工作折叠区**

17. 作为用户,我希望轮次完成后其过程(思考、工具、中间正文)收进"已工作 N 秒"折叠区,以便历史会话只留最终正文、干净可读。
18. 作为用户,我希望折叠区可手动展开回看完整过程,以便需要时检索细节。
19. 作为用户,我希望运行中的轮次强制展开过程,以便实时看到 agent 在想什么、做什么。
20. 作为用户,我希望中断或失败的轮次强制展开过程,以便看到失败前发生了什么。
21. 作为用户,我希望折叠区摘要行显示工时,以便估计该轮工作量。

**思考过程持久化**

22. 作为用户,我希望重启应用后仍能展开查看历史轮次的思考过程,以便回看当时的推理。
23. 作为用户,我希望切走再切回运行中会话后思考过程不丢失,以便内存重建与落盘恢复衔接。
24. 作为用户,我希望子代理的思考过程同样在重启后可回看,以便子代理卡内折叠块不空白。
25. 作为用户,我希望旧会话(无思考数据)正常打开,对应消息段自然缺失而非报错或出现空块。

**工具调用卡**

26. 作为用户,我希望工具卡折叠态显示工具名、参数摘要、状态与耗时,以便一眼扫过一轮做了什么。
27. 作为用户,我希望工具卡展开态分层显示参数与输出,以便需要时查看细节。
28. 作为用户,我希望运行中、成功、失败有可区分的状态标识,失败详情可查,以便快速定位问题。
29. 作为用户,我希望连续同类工具自动统计分组(如"Read × 5"),以便过程区不被重复卡片淹没。
30. 作为用户,我希望子代理卡作为消息段按时序出现,内嵌思考折叠与最终报告,以便主过程与委派工作关系清晰。

**宽度与布局**

31. 作为用户,我希望消息流在宽屏下放宽(上限 1152px),以便代码块、diff、表格有足够空间。
32. 作为用户,我希望宽度以会话容器为断点,侧栏开合不引起消息列宽度跳变,以便布局稳定。
33. 作为用户,我希望用户消息限宽右对齐、assistant 正文与工具卡全宽,以便输入与输出的层级一目了然。
34. 作为用户,我希望宽代码块与表格在自身容器内横向滚动,以便不撑破消息流布局。
35. 作为用户,我希望消息流、头部与输入区左右对齐共用同一内容列,以便视觉连贯。

**特殊项与兼容**

36. 作为用户,我希望错误、中断标记、compact 摘要作为消息段按时序出现在正确位置,以便上下文连贯。
37. 作为用户,我希望压缩后消息流只保留摘要与最近轮次的行为不变,以便既有心智模型不被破坏。
38. 作为用户,我希望阅读位置跨会话与重启的保存恢复精度不低于现状,以便不倒退。

## Implementation Decisions

- **数据模型(packages/ui 会话视图层)**:会话视图状态从"归类气泡列表"改为消息段时序序列。消息段类型集:思考段、正文段、工具调用卡、子代理卡、错误段、状态段、compact 摘要段、用户消息段。每段带会话内单调稳定序号(永不复用)与轮次标签;段间关联靠共享响应 id,不嵌套。轮次是段上的标签而非容器。历史恢复与运行期事件共用同一归并入口,恢复输出与流式输出形状一致。
- **更新操作封闭集**:尾部追加、按 id 整段替换(状态迁移)、截断删除、流式文本追加(仅允许追加到流态段)。表达不了的结构变化整体重放,不引入字段级 patch。
- **渲染三层**:单段视图按类型分派 → 轮次聚合(分组与间距的呈现单位)→ 轮内切分:以"最终正文"(轮内最后一段正文;无正文的轮全部过程入折叠区)为界,之前的过程段在轮完成后进已工作折叠区,之后的段跟随显示。折叠开合是渲染层内存态(按键记忆),不进数据层。
- **滚动跟随(packages/ui 新纯函数模块,无 DOM 依赖)**:FOLLOWING/DETACHED 状态机;距底 ≤48px 判定贴底;输入意图识别(滚轮/触摸/方向键翻译为朝向)+ scroll 事件滞后一帧的竞争对账(最近用户向上意图同帧让位);内容变化后跟随则贴底、脱离则保持;"回到最新"可见性 = 脱离跟随且有消息。贴底用直接 scrollTop 赋值;滚动容器 scrollbar-gutter 稳定、禁用原生 scroll anchoring(由状态机自管)。
- **阅读位置记忆**:按会话保存 scrollTop 及"离开时是否贴底";恢复时贴底标记→定位当前最新并跟随,否则恢复像素位置(按当前高度夹紧);无记忆→定位最新。与现有跨会话/重启恢复机制精度保持兼容(既有 <4px 断言不回归)。
- **reasoning 持久化(packages/agent-core + SQLite)**:主会话与子代理的思考文本随终态消息落库,新增列及迁移沿用现有 migration 机制;恢复路径把思考重建为消息段(运行期内存事件重放与落盘恢复衔接,不重复不丢失)。落库仅为展示,不改变"思考不回传 provider 上下文"的现行行为。旧数据无思考列值时消息段自然缺失,不做补录迁移。
- **宽度(packages/ui 布局)**:内容列以会话容器为断点分档:空态上限 672px 级(2xl);容器 ≥864px 时收窄留白且上限 896px 级(4xl);≥1280px 时上限 1152px 级(6xl)。消息流、头部、输入区共用同一内容列宽度类,宽度变化不做过渡动画。用户消息限宽右对齐气泡;assistant 正文与工具卡全宽;代码块/表格横向滚动内聚;滚动容器自身无横向溢出。
- **工具调用卡**:折叠摘要行=图标/类别词+动作摘要+状态标识+耗时;展开=参数与输出分层,失败详情在状态位可查;连续同类工具统计分组(组头计数,展开仍由原卡片渲染);子代理卡为消息段,内嵌思考折叠与最终报告,运行→完成边沿自动收起一次。
- **特殊项**:错误、状态、compact 摘要、中断标记统一为消息段类型按时序排列;对话内交互问答面板维持独立区域不入消息流。
- **性能**:本次不引入虚拟滚动与历史分页;消息段带稳定 key 且自包含,轮次聚合单位为将来虚拟化预留接口。

## Testing Decisions

- 好测试只断言外部可观察行为:DOM 中消息段顺序与折叠状态、滚动几何(贴底距离、位置恢复精度)、恢复后可见内容;不断言内部结构。
- **接缝一:会话视图 reducer 单测(vitest,现有接缝)**——时序序列归并(交错保真、封闭更新集)、历史恢复重建(思考段、子代理思考段、无思考旧数据)、内存重放与落盘恢复衔接。现有断言"历史加载不制造思考块"随新行为反转为"历史加载重建思考段"。
- **接缝二:滚动跟随纯函数单测(vitest,新接缝,packages/ui 内)**——状态机裁决、输入意图识别、竞争对账(用户上滚与同帧内容更新)、阅读位置恢复计算。竞争场景以纯输入重放,不依赖真实 DOM 时序。
- **接缝三:Electron e2e(playwright-core + mock provider,现有最高接缝)**——新增/扩展场景:跟随→上翻脱离→回到最新→恢复;严格 DOM 时序断言(思考/正文/工具卡交错轮次按事件序);宽度断言(assistant 内容实际宽度突破 768px 锁死、容器分档);重启后思考可回看;压缩摘要与特殊项位置。硬约束:现有 23 个 e2e 场景保持全绿(尤其阅读位置 <4px、thinking 折叠交互、工具卡、切换恢复类断言)。
- Prior art:会话视图与子代理视图现有 vitest 套件;e2e 的 thinking、smoke、live-sessions、interrupt、compact、exit-recovery、persistent-workbench 场景(其断言与 data-testid 惯例直接沿用)。

## Out of Scope

- 虚拟滚动、长会话渲染性能优化与历史向上分页(仅预留接口)。
- 消息级操作(fork、retry、编辑重发、复制按钮、悬停动作行)。
- 对话内交互问答面板(InteractionHistory)的呈现改动。
- 旧会话思考数据补录迁移;provider 上下文行为调整。
- 消息内嵌模型切换、时间线 marker 等扩展行类型(协议留扩展空间,本次不实现)。
- "回到最新"入口与工具卡摘要行的像素级视觉稿(实现时对齐主题 token,验收以行为为准)。

- 术语"消息段、轮次、跟随、已工作折叠区"以 GLOSSARY.md 为准;实施 PR 与代码注释沿用该词汇。
- 现有 `data-testid`(message-stream、message-assistant、thinking-block、tool-call-card 等)保持稳定,e2e 断言迁移成本最低;新增消息段级 testid 命名沿用同一惯例。
- 落库 schema 变更与迁移走 agent-core 现有 SQLite migration 通道,编号顺延。
