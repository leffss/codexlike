# 01: 时序消息段模型与按时序渲染

**What to build:** 会话视图数据层从"按类型归类合并的气泡列表"重构为按事件发生时序排列的扁平消息段序列:思考段、正文段、工具调用卡、子代理卡、错误段、状态段、compact 摘要段全部成为序列中的平等成员,带会话内单调稳定序号与轮次标签,段间关联用共享响应 id 而非嵌套。渲染层如实按时序呈现全部现有项(呈现形态可朴素,保持现有折叠交互),历史恢复与运行期流式输出共用同一形状。完成后,一轮"正文→工具调用→再正文"的交错回复在界面上按真实发生顺序显示——这是"思考/正文/工具调用显示混乱"的核心修复。[规格](../spec.md)时序保真与特殊项各组用户故事;取舍见 [ADR 0011](../../../../docs/adr/0011-message-stream-timeline-model-and-reasoning-persistence.md)。

**Blocked by:** 无(可立即开工)。

**Status:** ready-for-agent

- [ ] 消息段类型集完整覆盖现有全部项类型(思考/正文/工具卡/子代理卡/错误/状态/compact 摘要/用户消息),每段带会话内单调、永不复用的稳定序号与轮次标签
- [ ] 更新操作为封闭集:尾部追加、按 id 整段替换、截断删除、流态文本追加;表达不了的结构变化整体重放,无字段级 patch
- [ ] 思考与工具调用穿插交错的轮次在 DOM 中按事件发生顺序排列,新增严格顺序断言(不靠文本过滤)
- [ ] 工具调用之后产生的正文显示在该工具卡之后;思考段不再被提升到轮次顶部合并
- [ ] 历史恢复输出与运行期流式输出形状一致(同一归并入口)
- [ ] 会话视图、工具视图、子代理视图、live 会话的 vitest 套件随新模型重写并通过,覆盖交错保真与封闭更新集
- [ ] 现有 23 个 e2e 场景全部保持绿色(现有 data-testid 稳定不动)
- [ ] 现有折叠交互(思考折叠块、工具卡展开)在新结构下行为不变
- [ ] `pnpm typecheck` 与 `pnpm test` 通过(检查命令直接运行取退出码,不接管道)
