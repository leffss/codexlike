# 审批模式三档重构：请求批准 / 帮我批准 / 完全访问

## Context

现有审批三档 `readonly`（只读，写入与命令一律**拒绝**）/ `suggest`（协作，命令逐条审批）/ `full`（自主，全自动）需重构为新三档，语义变化是质变而非改名：

| 新档     | 内部值        | 语义（已与用户确认）                                                                                                     |
| -------- | ------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 请求批准 | `ask`         | 写文件、终端命令、联网搜索一律暂停等待审批；只读工具放行                                                                 |
| 帮我批准 | `assist`      | 工作区内写入与联网自动放行；命令按**危险黑名单**判定：命中→审批（且不可记忆 always），未命中→自动放行（always 记忆照旧） |
| 完全访问 | `full-access` | 一切放行 + **放开工作区文件硬边界**（不受限读写本地文件、联网）；切换时 UI 弹风险确认                                    |

已确认的三个决策：① 内部标识符改新值 + 旧库读侧迁移（`readonly→ask`、`suggest→assist`、`full→full-access`）；② 危险命令黑名单谓词；③ `ask` 档管控口径为写/命令/联网全询问。

注意：`ask` 档用户点「总是允许」仅放行本次、**不写记忆**（"始终询问"语义）；`assist` 档非风险命令保留 always 记忆（现状行为）。

## 改动清单

### 1. agent-core 审批状态机 — `packages/agent-core/src/session/approval.ts`

- `ApprovalMode = 'ask' | 'assist' | 'full-access'`；导出 `APPROVAL_MODES` 常量数组（IPC 校验与 UI 复用）。
- 新增 `isRiskyCommand(command: string): boolean`：危险首词黑名单（`rm`/`del`/`erase`/`rmdir`/`rd`/`format`/`mkfs`/`dd`/`sudo`/`npm publish` 首词组合等）+ 危险模式（`git push --force|-f`、`git reset --hard`、`git clean`、`curl|sh`、`powershell -Command` 管道注入等），Windows 大小写不敏感。
- `decideApproval` 重写四分支：
  - `permission === 'readonly'` → 任何模式 auto（不变）；
  - `network`（web_search）→ ask 档 ask / assist、full-access auto；
  - `write` → ask 档 ask / assist、full-access auto；
  - `command` → ask 档一律 ask；assist 档 `isRiskyCommand` 命中→ask 且 `ApprovalGate.ask` 增加标记（见下），未命中→记忆命中 auto、否则 auto；full-access auto。
- `ApprovalGate` 的 `ask` 分支加 `risky: boolean` 字段：`agent-session.ts:543` 与 `subagent.ts` 的 always 记忆逻辑按它跳过（风险命令 / ask 档不写 `approvalMemory` 与 `insertApproval`，但本次仍执行）。
- 删除 readonly 的 `blocked` 分支相关文案；`blocked` 保留（防御性，新语义下不可达可保留类型）。

### 2. 工具权限分类 — `packages/agent-core/src/tools/types.ts` + `web-search.ts`

- `ToolPermission` 增加 `'network'`；`web-search.ts:143` 的 `permission: 'readonly'` 改 `'network'`（其余工具不动）。

### 3. 完全访问放开工作区硬边界

- `ToolExecutionContext`（`tools/types.ts:17`）加 `approvalMode: ApprovalMode` 字段。
- `tools/workspace.ts` 新增 `resolvePath(workspacePath, target, mode)`：`full-access` → 绝对路径直接 `resolve`、相对路径相对 workspacePath，**不做边界断言**；其余模式 → 现有 `resolveInWorkspace` 原逻辑。
- 6 个调用点换新函数（读+写+glob+grep+terminal cwd）：`read-file.ts:43`、`write-file.ts:36`、`apply-patch.ts:78`、`glob.ts:38`、`grep.ts:58`、`terminal.ts:196`。
- context 填充点：`agent-session.ts:548-554`、`559-565` 两处 `runTool`，及 `subagent.ts` `gateAndRun` 内的执行点。

### 4. 持久化迁移 — `packages/agent-core/src/session/persistence.ts`

- SCHEMA 与 ALTER 的默认值 `'suggest'` → `'assist'`（`:61`、`:167`）。

- 新建默认与兜底：`manager.ts:164`、`agent-session.ts:260` 改 `'assist'`。
