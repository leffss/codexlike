# 新建任务：居中起点式布局（变体 A「决策台」），项目归属选择入页面

新建任务态此前复用正式任务的聊天布局（空消息流 + 底部 composer + 一行工作区信息），实测痛点：近乎空白的页面没有「新建时刻」的起点感，工作区/模式等新建时的高决策项层级错位。经三变体原型对比（分支 prototype/new-task-start：A 决策台 / B 输入为王 / C 一体化控制台，均挂在真实工作台外壳内以 DEV + `?prototype=new-task` 门控评判），用户选定**变体 A「决策台」**并按反馈修订四项后定稿：内容列 800px、决策行去技能、标题行右侧项目选择器、发送按钮用 composer 同款圆形上箭头图标。

## 关键边界

- **专属布局，不复用聊天结构**：新建任务态主列为居中起点式（垂直居中、max-w 800px、纯起点留白——不放最近任务/示例，回访归侧栏）；标题栏保持品牌回退，项目身份由一级工作区项承载；首条发送成功后即时硬切任务视图（失败回退语义不变）。正式任务的 MessageComposer 与消息流布局零波及。
- **一级决策项四组**：项目归属、工作区（路径 + 本地/Worktree 模式，项目任务；独立任务为专用目录/选择已有目录）、审批模式、模型与思考档位——围绕输入卡上方一级呈现（工作区单独成卡）。模型与思考档位现已合为一个入口，见下文「选择器呈现修订」。**技能不入一级**（对需求访谈共识的修订）：输入框 `$` 直调、随首条消息生效，placeholder 提示承载发现性。
- **归属选择入页面**（对「入口模型不变」共识的修订）：标题行右侧「项目」选择器，可选某个项目或「不选项目（独立任务）」，切换即改工作区行形态；由此侧栏顶栏「+」菜单的三选项（独立/各项目）退役为单一「新建任务」按钮直达，项目组头/独立组头悬停「+」保留为带语境直达。
- **无 Provider Profile**：起点卡整体替换为配置引导卡（品牌语 + 主按钮直达设置）。
- **文案去「草稿」化**：用户可见面统一「新建任务」心智（如「发送第一条消息后创建任务」），不出现「草稿」；内部标识符（NewTaskDraft、draft-* testid）不动。
- **域语义一寸不动**：首条发送才创建任务、草稿按入口持久化、requestId 幂等与失败补偿、独立入口无 Worktree、工作区首次执行后固定——本 ADR 只动呈现层与入口形态。

## 选择器呈现修订

后续「模型与思考档位统一选择器」原型选定 B 方案（与本 ADR 的整页布局变体编号无关）：在原决策行位置使用同一组合控件，顶部提供商下拉、中部模型、底部思考档位；正式任务也采用该共享控件，但仍位于输入框底栏。具体交互与稳定定位要求见 [ADR 0024 的呈现修订](0024-provider-profile-multi-model.md)。该修订不改变本 ADR 的居中起点、工作区与项目归属布局，也不改变首发与记忆语义。

## 取舍

- 拒绝变体 B（输入为王：大输入卡 + 卡下轻 pills）与 C（一体化控制台：决策带/输入/发送熔进一张卡）：全套变体与切换器留 prototype/new-task-start 分支作一手材料。A 胜出理由：决策先行的信息层级与「新建是配置时刻」的心智最贴合，工作区单独成卡让最重决策获得匹配的视觉重量；反馈修订后四个一级决策 + 输入卡的密度恰好。
- 拒绝向导分步式（先配置后输入多一步确认）：与「首条发送才创建」的轻量心智相抵触。
- 拒绝新建页放最近任务/示例提示词：任务回访由侧栏承担，重复呈现违反单一职责；示例提示词对 coding agent 场景价值低。
- 技能曾定为一级决策项，原型反馈推翻：消息中 `$` 直调更贴近使用时机（技能随消息生效），一级呈现反而制造「任务级配置」的误导。

影响面：WorkspacePage 草稿态分支整体替换为新建任务组件（新建态专属输入卡壳，复用 MessageComposer 的选择器/菜单子件）；TaskSidebar 顶栏「+」菜单简化；e2e entry-consistency 的入口断言语义随之变更；GLOSSARY 已加「新建任务」词条；原三变体与场景切换器不进 main（prototype/new-task-start 分支）。
