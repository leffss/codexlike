# 目标模式：任务级持久目标，完成判定驱动的跨轮续跑

背景：用户诉求「添加目标模式」——现有任务是对话驱动（每个回合都由用户消息触发，跨回合 auto-continue 不存在），缺「给一个目标、agent 自主跑到完成」的长期执行形态。参照物二选一：OpenAI Codex Goal mode（`/goal`，完成标准内嵌于目标文本，模型每轮自判、自然结束）与 ZCode goal（`/goal`，显式 verifier 每轮独立判定）。经三轮拷问定案：**机制主干学 ZCode，产品面学 Codex，护栏两者兼收**。

## 关键边界

- **正交轴**：目标模式只改变「跑到什么时候停」，不改变权限语义——可与任意审批模式组合；审批等待照旧（任务转 waiting-approval 等用户，恢复后继续循环）。
- **任务级**：一个任务同时至多一个目标（目标实体挂在任务上，不引入跨任务的更上层实体）；目标原文同时充当首条指令与完成判定标准（引导用户写 期望结果/约束/验证方式 三要素）。
- **续跑循环**：一轮正常回合（工具照常、单回合工具轮次上限照旧适用）→ 完成判定（任务当前模型、无工具、读目标文本 + 完整消息历史，返回 通过/理由/下一步方向）→ 未过则携带判定反馈续跑下一轮；续跑轮是内部输入，不产生用户气泡。
- **状态机六态**：进行中（验证中为进度行副状态）/ 已暂停 / 已完成 / 未达成（连续 3 空转轮触发）/ 预算受限 / 已清除；判定请求自身故障（网络/坏输出）走 fail-open，不设独立用户态——该轮如实显示「判定不可用」，验证记录以结论种类 `passed / unpassed / unavailable` 在数据面区分（`unavailable` 不代表未达成），连续 3 轮故障复用「已暂停」态暂停、出现正常结论即清零（与实现对齐，见 goal-mode 票 07）。
- **控制面**：`/goal <目标>` 斜杠命令入口 + 输入框上方目标进度行（目标摘要、状态·第 N 轮、累计时长、暂停/恢复/编辑/清除按钮）；Stop 按钮 = 暂停。新建任务页（首条消息前、任务尚不存在）同样可用 `/goal`：提交即用该页的归属与发送偏好建任务、设目标、目标原文作首条用户消息开跑——与任务态同一语义（目标原文即首条指令）；首轮启动失败沿用首次发送的回滚（任务与目标同滚，命令回填输入框）。被拦命令与用法提示不清空输入（与忙时命令「输入已保留」同口径；新建任务页的 `/goal` 由宿主在建任务时消费草稿文本）。编辑只在已暂停 / 预算受限 / 未达成可用（进行中先暂停）；目标进行中其余斜杠命令沿用「忙时命令不入队」、不放行（与实现对齐，见 goal-mode 票 07）。
- **暂停阀门**：目标激活期间用户消息进输入队列但**不自动消费**，暂停或完成后恢复自动逐条发出——完全复用现有输入队列机制与语义，零特判。
- **护栏**：token 预算是目标级参数（进度行上设定，缺省不限，`/goal` 不带预算参数）——消耗 = 目标设定以来任务用量账目的增量（设定时拍基线，含主任务各轮、子代理、压缩与判定自身），对账在每轮判定之后，用量达到预算（`≥`）即转「预算受限」暂停（非终止）；连续 3 轮判定未过且无实质工具活动 → 「未达成」暂停，空转阈值 3 为定值、不做配置项。「实质工具活动」只认实际执行了的工具调用（被拒 / 参数无效 / 未注册的不算，执行出错仍算，`update_plan` 除外）。处置优先序：完成 > 判定连续不可用暂停 > 未达成 > 预算受限（「用量达到预算即超」与「完成优先于预算」是票 05 的细化、规格未写，见 goal-mode 票 07）。
- **呈现**：`/goal` 原文作为用户消息正常显示；每次判定 = 消息流单行标记行（「第 N 次迭代 · 验证中/已完成/未完成/判定不可用」，未完成附下一步方向一句摘要；「判定不可用」是判定自身故障、如实呈现不写成未完成——与实现对齐，见 goal-mode 票 07）；不做迭代摘要卡；过程胶囊条维持三胶囊不加第四个。
- **其他照旧**：工作计划与目标两层并存（计划 = 阶段步骤清单、目标 = 整体目的地，update_plan 在续跑轮内照常工作）；目标激活任务占任务并发上限一席照旧；`/compact` 激活期间禁用（压缩会重写判定所依赖的完整历史，提示先暂停），暂停期间照常可用。

## 取舍

- 拒绝 Codex 内嵌式完成判定（零额外调用但不可观测、完成与否全凭模型自觉）：显式判定的逐轮结论可落库、可 e2e 断言，与仓内留痕文化（ADR 0021 子代理记录）一致；代价是每轮一次无工具小请求，成本远低于一轮工作。
- 拒绝 steering（运行中用户消息直接注入下一轮续跑指令，Codex 式）：绕过输入队列语义，需特判「等待用户交互期间输入框不可用」等既有规则；暂停阀门改动最小、语义不打架，steering 留作后续演进。
- 重启恢复为**暂停态**、用户手动恢复——与两参照物（daemon 重启后自动续跑）相左：重启后无人值守自动消耗 token 不符保守口径（对照：任务排队重启后自动开跑是用户已显式排队的首条执行，目标自动续跑是重启前未必预期的持续消耗）。停机时长不计入累计时长：进行中区段闭合在该任务落库里最晚的时间戳上、并夹在 `[activeSince, 重启时刻]` 之间，落库里没有更晚记录时按 0 计（编排者裁决，规格未写，与实现对齐见 goal-mode 票 07）。
- 状态集比 ZCode 七态少一：拒绝 notSatisfied/failed 两分（判定有效未过 vs 判定过程失败）——判定过程失败由 fail-open 吸收，「未达成」只留空转阻断触发口径，不再为「有效未过」单独成态（未过即续跑，是循环的常态而非状态）。
- 新建任务页的 `/goal` 取「建任务并开跑」而非把目标暂存到首条消息再设：暂存会让首条消息 ≠ 目标原文，破坏「目标原文同时充当首条指令与完成判定标准」的契约，且新建任务页没有进度行位置展示待生效的目标。

影响面：agent-core（续跑循环、完成判定请求、目标实体与状态机、任务循环 idle 边界）；desktop（目标落库与重启恢复为暂停态、类型化 IPC、输入队列互锁、`/goal` 命令解析、新建任务页设定目标）；ui（目标进度行、判定标记行、侧栏运行口径、斜杠命令分发与新建任务页输入保留）；desktop e2e 新场景；GLOSSARY 新增「目标 / 目标模式 / 完成判定」三词条（与既有「工作台目标（Workbench Target）」撞「目标」二字，靠全称与语境区分，见词条 Avoid 标注）。
