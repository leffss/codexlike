# 会话工作台：项目归属与执行工作区分离

本次会话管理重构采用独立项目实体及可选项目归属：项目由用户添加并独立于会话存在，会话可以归属一个项目或成为侧栏单独组织的独立会话。该选择替代 ADR 0005 的目录自动派生项目规则，因为按目录推导归属无法同时表达空项目和使用项目目录但不归属项目的会话。用户已逐项确认这些产品决策；本文记录目标设计，业务代码尚未实施。

## 关键边界

- 工作区是实际执行任务的目录，项目是管理归属。项目会话使用项目目录或其托管 Worktree；独立会话默认使用应用分配的专用持久目录，也可在首次发送前指定目录。首次执行开始后工作区固定，调整项目归属不改变目录、分支和历史。
- 非执行中且没有等待用户回应的会话可以调整归属：独立会话只可移入目录匹配的项目；项目会话可移出成为独立会话。Worktree 会话移出后保留来源信息，只能移回来源项目。首版不从独立会话入口直接创建 Worktree。
- 查看会话与执行任务彼此独立。切换后运行、等待用户交互以及正在生成的正文和工具记录保持完整；退出应用则中断执行和等待，重启恢复工作现场但不自动续跑或重放工具，沿用 ADR 0009。
- 新建入口先产生草稿，首次发送才创建正式会话和所需目录或 Worktree。项目内默认本地模式，首次发送前可选 Worktree；同目录本地会话并行时提示共享文件风险，不全局禁止并行。
- 模型选择、思考档位、审批模式按会话持久记忆，调整仅影响下一次发送，不改变已开始的执行；新会话采用应用默认模型和思考档位，审批模式从 `ask` 开始，`full-access` 仍需显式开启。此处改变的是设置归属，不改变 ADR 0004 的权限含义和 ADR 0008 的 provider 实现选择。
- 会话归档不删除磁盘文件；移除项目经确认后移除项目及其所属会话记录，但不删除项目目录或 Worktree 文件。取消按数量自动清理 Worktree 的旧规则，磁盘清理与会话整理分开；有执行或等待回应时先停止，才能归档或移除。
- 不兼容旧会话管理数据，不提供旧库迁移验收；这不要求更换 SQLite、突破类型化 IPC 或让 Agent Core 依赖 Electron，也不授权删除用户项目文件。

## 取舍

拒绝继续用目录派生项目，因为无法表达显式归属；也拒绝用“移动会话”暗中切换工作区，避免历史上下文与实际操作目录错位。选择手动恢复而非退出后的常驻执行或自动续跑，避免重放已经产生副作用的命令。取消自动清理会增加磁盘占用，但防止会话整理意外删除尚未收回的工作成果。
