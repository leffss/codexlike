# 消息流：时序行模型、跟随状态机与 reasoning 持久化

消息流重构把"按类型归类合并"的气泡模型改为按事件发生时序排列的扁平消息段序列，配显式跟随状态机与容器查询分档宽度；reasoning（思考过程）落库仅用于恢复后展示。设计参考 ZCode Web timeline 的公开源码调研（见 [调研报告](../research/zcode-message-stream.md)），借鉴其设计思想，不复制代码。产品决策已在 grilling 会话中由用户逐项确认。

## 关键边界

- 数据模型：消息段（thinking 段、正文段、工具调用卡、子代理卡、错误段、状态段、compact 摘要段）是时序序列的基本呈现单元，带稳定序号与轮次标签；轮次是段上的标签而非容器，段间关联靠共享响应 id 而非嵌套。更新操作保持封闭集：尾部追加、按 id 整段替换、截断删除、流式文本追加；表达不了的结构变化整体重放，不发明字段级 patch。
- 呈现分层：轮次分组用细分隔线与轮间距，不加 agent 名头/头像。轮内以"最终正文"（轮内最后一段正文）为界：之前的过程消息段在轮次完成后整体收进"已工作 N 秒"折叠区，之后的消息段跟随显示；运行中的轮与中断/失败的轮强制展开过程区。折叠开合是渲染层内存态（按段 id 记忆），不进数据层。
- 滚动跟随：显式 FOLLOWING/DETACHED 状态机，距底 ≤48px 视为贴底；只有真实用户输入（滚轮、触摸、方向键）能改变跟随态，程序化贴底与布局变化产生的滚动不动状态机；提交新 prompt 强制回底；脱离跟随时提供"回到最新"入口。贴底用直接 `scrollTop` 赋值，不用 smooth scroll。
- 阅读位置：按会话记忆，记忆包含"离开时是否贴底"；恢复时若当时贴底则直接定位到当前最新并继续跟随，否则恢复保存的像素位置；无记忆（新会话）定位最新。
- reasoning 持久化：主会话与子代理的 reasoning 随终态消息落 SQLite（新增列及迁移），仅为重启/切回后的展示；与"reasoning 不回传 provider 上下文"（agent-core 现行行为，见 `packages/agent-core/src/session/types.ts` 的 `assistant-reasoning` 注释）互不影响。旧会话无该数据时对应消息段自然缺失，不做旧数据迁移。
- 宽度：新建、未选择、加载中与已有会话统一以外层会话容器（非浏览器视口）为断点分档，不再为空态设置窄列；容器 <864px 时内容列全宽，≥864px 时上限 max-w-5xl，≥1280px 时上限 max-w-7xl（2026-11-22 应用户调宽诉求自 max-w-4xl/max-w-6xl 各上移一档，断点与留白结构不变）。标题、工作区信息、消息流与输入区同属主列、共用同一内容列宽度类，规范与技能/改动面板为主列的兄弟节点；面板开合压缩主列可用空间，但不改变外层容器断点。消息滚动区使用稳定滚动槽，按实际滚动槽宽度同步补偿非滚动区域，禁止硬编码平台滚动条像素；内容出现滚动条、加载与空态切换均不得造成左右缘跳动。标题保持单行省略，操作按钮不收缩。用户输入限宽右对齐气泡，assistant 正文与工具卡全宽；代码块与表格的横向滚动内聚在各自容器内。
- 工具调用卡：折叠态为工具名 + 参数摘要 + 状态标识 + 耗时；展开态分层显示参数与输出；连续同类工具自动统计分组（如"Read × 5"）；子代理卡为消息段，内嵌自身 thinking 折叠与最终报告。
- 特殊项（错误、状态、compact 摘要、中断标记）统一为消息段类型按时序排列；对话内交互问答面板维持独立区域，不入消息流。
- 性能：本次不做虚拟滚动与历史向上分页；数据模型保留稳定 key 与消息段自包含，为将来引入虚拟化留增量接口。

## 取舍

拒绝在渲染层修补归类气泡模型：时序交错在数据层归并时已丢失，渲染层无法恢复。拒绝 reasoning 只保内存：主进程事件缓冲随每次执行重置且不落盘，切会话与重启后思考过程不可回看。拒绝一刀切 max-w 或纯全宽：前者过窄（768px 锁死），后者在宽屏下行长失控，分档收窄兼顾两者。虚拟滚动暂缓：当前痛点是时序、滚动与宽度而非渲染性能，"已工作"折叠区收起后历史 DOM 已大幅减少，先落地模型，待真实卡顿出现再按预留接口加虚拟化。

完整决策过程与验收口径见本 ADR 引用的调研报告及后续 spec。
