# 持久会话自动批准与文件访问权限分离

用户需要在单次批准之外，明确授予当前会话持续执行权限。采用独立、可撤销、跨重启保留的会话自动批准，而不是切换到 `full-access`：减少反复审批不应附带放开文件工具的目录边界。此决定替代 ADR 0004 中禁止会话授权记忆、ADR 0009 中审批响应只能授权单条操作，以及 ADR 0010 中不恢复任何旧授权的对应约束；基础审批模式和恢复执行的其他规则不变。

## 授权边界

- 仅可从有效的待处理执行审批启用；一次显式操作同时批准当前会话所有已排队的执行审批，涵盖主代理和子代理，并自动批准后续轮次的执行审批。问答仍等待用户回答，其他会话及新会话不继承。
- 界面保留“批准本次”和“拒绝”，说明会话授权包含危险命令、已排队请求及重启后的继续使用；持续展示状态和取消入口。停止执行、切换会话或调整基础审批模式不隐式清除授权。
- 授权启用及取消即时影响后续审批判定，不撤回已获准的操作；基础审批模式仍按发送时快照生效。取消后恢复当前执行的基础审批策略，不承诺每个工具都重新询问。
- 自动批准只改变执行审批，不改变文件工具路径校验或基础模式。终端命令没有操作系统沙箱，保留文件工具边界不代表命令无法影响工作区外文件。
- 重启保留明确授予的会话授权，但仍取消未完成的交互，不恢复等待者、不重放工具、不自动续跑。

## 一致性与兼容

会话授权写入与全部待审批记录的结算必须原子提交；成功后先更新运行态，再通知并唤醒执行。保存失败、过期请求、重复提交或跨会话回应均不能授予权限。批量批准保留逐条历史和会话授权作用域。

旧的无作用域批准响应仍是单次批准；遗留 `always` 入口也保持单次语义，旧命令首词授权表不参与新策略。这样不会把历史残留数据或旧客户端的一次点击升级成持续授权。
