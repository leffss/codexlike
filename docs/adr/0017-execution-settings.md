# 执行设置：agent 执行参数的用户可调范围与注入模式

一批硬编码在 agent-core 循环内的执行参数有真实的用户可调需求：大功能开发单回合动辄上百次工具调用，200 轮上限对换更大上下文窗口的用户有上调动力；子代理报告被截断会让主任务多轮返工；终端跑构建/测试 30s 默认、120s 上限经常不够；compact 保留多少现场、上下文告警早晚都属个人偏好。决定把六个参数提取为用户设置：主任务/子代理工具轮次上限、压缩保留对话轮数、上下文告警阈值进新建的「执行」设置分区（独立 agent-settings.json），终端命令超时与最大命令超时进现有终端分区（terminal-settings.json 扩展）——超时语义属于终端配置而非 agent 执行。默认值全部保持现状（200/200/3/80%/30s/120s），只暴露「用户可能想调」的参数；防护性上限（AGENTS.md 注入体积、@引用大小、文件树扫描深度、read-file/grep 输出截断等）不进设置——它们是护栏不是偏好，暴露出去只会诱导误调，剩余候选（MCP 调用超时、浏览器工具超时、web_search 结果数等）留待后续按需分拣。

## 关键边界

- 注入模式沿用子代理并发上限的 resolver 范式：设置存主进程 JSON 文件，agent-core 经 options 收到逐次解析的取值函数，不直接依赖任何存储实现（ADR 0002 的边界不破）；子代理并发、终端 shell、搜索源三条既有链路同构。
- 生效语义「即时保存、回合开始快照」：设置改动立即落盘并生效于后续回合，已开始的回合用回合开始时读取的值——避免进行中回合的上限被中途调小后行为突变；/compact 与上下文告警无「进行中」状态，逐次读取。
- 主任务撞限的落库 error 提示与子代理报告截断标记改为携带当前上限动态值，替代固定数字文案（ADR 0016 引入的两处文案）。
- 校验范围：工具轮次上限 10–1000、压缩保留轮数 1–10、告警阈值 50–95%、命令超时 5–600s、最大命令超时 10–1800s 且命令超时 ≤ 最大命令超时；非法输入回退默认值。

## 取舍

拒绝「一项合并管主任务与子代理」：两者撞限语义不同（主任务中断用户回合，子代理仅截断报告回流），合并失去独立调整能力。拒绝「进行中回合即时生效」：调小上限会立即截断正在跑的回合，行为不可预期。拒绝把上下文窗口缺省值再暴露：Provider Profile 已可逐模型配置，重复入口反而分叉。拒绝「重启应用生效」：resolver 范式下即时生效无额外成本，重启只带来困惑。拒绝为设置项新建事件或总线：设置读取发生在回合开始等确定性时点，逐次解析足够。

影响面：agent-core 的任务创建选项与子代理配置扩展 resolver 字段（工具轮次上限×2、压缩保留轮数、告警阈值），主任务循环、子代理循环、compact、context-warning 四处消费点改读注入值；desktop 新增 agent-settings 存储与 IPC，terminal-settings 扩展超时两项，内置工具工厂注入；ui 设置页新增「执行」分区、终端分区补两项；GLOSSARY 新增「工具轮次」「执行设置」词条；其余候选参数清单以 needs-triage issue 留档。

## 落地补记（实现审查确认的三处实际形态）

- 读取侧越界统一回退默认：UI 层按分区两种防护并存——「执行」分区非法输入回退默认并写回输入框（用户可见回退结果），终端分区保存前阻止（spec user story 5 允许阻止或回退二者）；主进程各 store 读取侧（含手改文件）六项一律回退该项默认值，不夹紧——夹紧会把越界值悄悄变成另一个「合法」值，掩盖误配。终端两项的联动校验失败（命令超时 > 最大命令超时）读取侧整对回退各自默认，与保存侧的联动拒绝语义对齐。
- 上下文告警阈值的注入路径与三项 resolver 不同：告警评估点在渲染层（ui `lib/context-warning.ts`，WorkspacePage 告警提示消费），每次评估经 IPC 逐次读取 agent-settings，不经 manager/task resolver 装配——agent-core 任务循环不消费告警，`evaluateContextWarning` 以纯函数参数接收阈值占比。
- 子代理工具轮次上限的「回合开始」快照点：子代理无独立用户回合，「回合开始」映射为子代理开始运行时读取一次（runSubagent 内）；排队未开跑的按开跑时的值解析，运行中不受中途调小影响。
