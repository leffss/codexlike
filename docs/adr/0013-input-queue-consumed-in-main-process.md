# 输入队列由主进程消费并随会话持久化

会话忙时用户提交的消息排入每会话独立的输入队列，空闲后自动逐条发出。队列的消费引擎放在 Electron 主进程并随会话持久化到 SQLite，而不是渲染层：队列是会话的属性而非「当前查看哪个会话」的属性，与「切走不打断执行」的既有架构一致；跨重启保留，重启后自动继续消费。

## Considered Options

- **渲染层消费**（拒绝）：队列存 workspace-state、消费循环在 WorkspacePage，实现最简；但后台会话的队列永不推进，「每会话独立队列」名存实亡，重启后恢复消费也无从谈起。
- **主进程消费**（选定）：队列与消费循环位于 session-ipc 层，会话一空闲即推进，与用户正在查看哪个会话无关；代价是队列操作（入队/编辑/删除/重排/暂停/恢复/清空）需要一套 IPC 协议，且队列需要持久化 schema。

## Consequences

- 发送参数（Provider Profile、思考档位、审批模式）必须在**入队时快照**随消息保存：主进程消费时无法读取渲染层的当前值。
- agent-core 的 busy 互斥保持不变，队列调度完全位于 desktop 主进程层，agent-core 不感知队列存在。
